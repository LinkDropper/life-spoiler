# 에러 처리 규칙

버그를 수정하거나 새 에러 케이스를 처리할 때 참조한다.

- 커스텀 에러 클래스 사용 권장
- 에러 메시지는 한국어로 작성 (사용자에게 노출되는 경우)
- 에러에 컨텍스트 정보 포함

```typescript
throw new OAuthError("토큰 교환에 실패했습니다.", {
  code: "TOKEN_EXCHANGE_FAILED",
  provider,
  httpStatus: response.status,
});
```

## 근본 원인 우선 원칙

- 증상을 숨기는 방어적 try/catch, 에러가 안 나게 만드는 기본값 채우기, 조건부 스킵은 지양한다.
- "왜 이 값이 이런 상태로 도달했는가"를 역추적해 근본 원인을 먼저 파악한다.
- 상류(upstream)에서 잘못된 값이 내려온 것이 원인이면 하류에서 방어하지 말고 상류를 고친다. 하류 방어가 정당한 경우는 입력이 외부 경계(사용자, 외부 API)에서 왔을 때뿐이다.
- 판단 기준: "이 수정을 revert하면 원래 에러가 다시 나는가?" 안 난다면 증상 회피 수정이므로 폐기한다.
