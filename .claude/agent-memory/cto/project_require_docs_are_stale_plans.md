`require/*.md`의 구현 계획서는 "앞으로 할 일"이 아니라 **이미 실행이 끝난 과거 계획서**인 경우가 있다. 확인된 사례: `require/yearly-fortune-plan.md`(유년/올해운세)는 문서상 미착수처럼 읽히지만 실제로는 전부 구현·커밋되어 있고, 스펙 범위를 훨씬 넘어(도화 분석, 삼방사정, yearly_2027 에디션, i18n, 캐시, 폴백) 수십 커밋에 걸쳐 고도화된 상태였다.

**Why:** 이 문서들에는 체크박스(`- [ ]`)가 미체크로 남아 있어 미착수로 오인하기 쉽다. 실제로 상위 조율자가 이 문서를 근거로 "신규 기능 구현"을 지시한 적이 있고, 그대로 IC 3명을 스폰했다면 이미 동작 중인 프로덕션 코드를 재작성할 뻔했다.

**How to apply:** `require/`나 `specs/`의 계획서를 근거로 위임 지시를 받으면, IC를 스폰하기 **전에** 먼저 `ls`/`grep`으로 해당 산출물 파일의 존재와 `git log -- <경로>`를 확인한다. 이미 존재하면 위임하지 말고 즉시 상위에 "전제가 어긋남"을 보고한다. 확인 비용은 툴 콜 2~3회로, 잘못된 스폰 한 번보다 훨씬 싸다. 관련: [[feedback_incremental_delegation]]
