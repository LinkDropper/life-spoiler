IC에게 여러 항목이 묶인 작업을 위임할 때는 **(1) 항목에 실행 순서를 매기고, (2) "하나를 끝낼 때마다 즉시 파일을 저장하라"고 명시하고, (3) 가장 단순한 항목을 1번에 두고, (4) 막히면 거기 매달리지 말고 끝낸 것까지 저장 후 보고하라**고 지시한다.

**Why:** 2026-08 인생운세 P0 작업에서 `fullstack`에게 3개 항목(UI 조건 수정 / 캐시 버저닝 / 후기 게이트+i18n)을 한 번에 위임했더니, **1시간 30분 동안 파일 변경이 단 하나도 없이** 진행 상황 문의 2회에도 무응답으로 끝났다. 전체를 완벽히 설계하려다 아무 산출물도 못 남긴 것으로 보인다. 동일 범위를 순서·증분 저장 지시와 함께 재위임하니 정상적으로 하나씩 커밋 가능한 상태로 완료됐다.

**How to apply:**
- 위임 직후부터 `git status --short`로 폴링해 산출물이 나오는지 확인한다. **20~30분 내 파일 변경이 0이면 정상 신호가 아니다.**
- 멈춘 IC는 `TaskStop`으로 못 죽일 수 있다(`owned by ...; cannot stop it` 에러). 이 경우 새 에이전트를 이름 붙여(`name` 파라미터) 재기동하는 게 빠르다. 멈춘 쪽이 파일을 하나도 안 건드렸다면 충돌 위험은 사실상 없다.
- 병렬 트랙을 돌릴 땐 각 IC에게 **"상대가 어떤 파일을 만지고 있으니 건드리지 말라"**를 명시한다. 파일 집합은 서로소여야 한다 ([[parallel-track-file-ownership]] 참조).
- IC가 검증(tsc/lint/build)까지 못 하고 끝나면 CTO가 직접 돌려도 된다. 단 `pnpm lint`는 `scripts/**`에 **기존 baseline 에러가 55건 있어** 전체 실행 시 항상 실패한다 — 변경 파일만 지정해 `npx eslint <files>`로 판정해야 한다.
