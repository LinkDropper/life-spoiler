# 인생 운세 해석 품질 개선 설계

**작성**: 2026-11-06
**참여**: 자미두수 전문가(ziwei-expert), AI 개발(ai-dev), 그로스(growth-strategist) 진단 종합
**근거**: 운영 DB 읽기 전용 조회(결제 완료 인생 운세 ko, 최근 120일, n=97), reviews, follow_up_questions, 코드 추적
**범위**: 인생 운세(lifetime). 올해 운세·궁합은 같은 시스템 프롬프트 블록을 공유하므로 Phase 2 이후 같은 방식으로 확장.

---

## 1. 한 줄 결론

"재미없다·뻔하다"는 문체 문제가 아니라 **구조 문제**입니다. LLM은 무엇이 이 사람에게 특이한지 모르는 상태에서, 근거는 대되 근거 용어는 쓰지 말고, 사람들이 실제로 묻는 시기·직업·배우자는 피하고, 60~100자 안에 쓰라는 요구를 받습니다. 그래서 모델은 어느 명반에나 맞는 생활 조언("기록·정리·분리·흔들림")으로 빈칸을 채웁니다.

해법은 **엔진이 '이 사람의 사실'을 결정적으로 뽑고, LLM은 그것을 서술만 하게 하는 구조**입니다. 이 방식은 관상스포 동질화 문제에서 가장 크게 통했습니다(reference/performance-analysis/07, Phase 18).

## 2. 근거

### 2-1. 실제 출력은 사람마다 거의 같다 (n=97)

| 지표                                        | 측정값                               | 의미                              |
| ------------------------------------------- | ------------------------------------ | --------------------------------- |
| 스포일러 headline에 "흔들" 포함             | **52%** (50/97)                      | 절반이 같은 콘셉트                |
| headline이 "~사람/결/흐름/힘/감각"으로 끝남 | 46%                                  | 문법 구조도 수렴                  |
| oneLiner에 "길" / "멀리·오래"               | 37% / 28%                            | "~하되, ~하면 길이 열린다" 템플릿 |
| 해석 전체에 "기록"                          | **91%**                              | 명반과 무관한 범용 조언           |
| "분리"(통장·지출 분리) / "정산"             | 60% / 24%                            | 같은 재물 조언 반복               |
| 직업 점수                                   | 평균 84.4, **표준편차 2.5**, 최대 89 | 점수가 사실상 상수                |
| 재물 점수                                   | 서로 다른 값 10개, 표준편차 4.0      | 변별력 없음                       |
| 건강 점수 최솟값                            | 67                                   | 낮은 점수가 거의 없음             |

- "흔들" 헤드라인 12건의 명반은 명궁 지지 8종, 오행국 5종으로 모두 다릅니다. **서로 다른 명반이 같은 헤드라인을 받습니다.**
- 사화 구성이 완전히 다른 두 사람(샘플1: 화록 태양/화기 천동, 샘플2: 화록 천기/화기 태음)이 "결단·정리·기준·흔들림·속도 조절"이라는 같은 어휘와 "문서로 남겨라 / 계약과 기준을 먼저 세워라"라는 같은 조언을 받았습니다.
- 금지 규칙 위반도 실제로 일어났습니다. 샘플2 인연 본문에 "자미의 품위와 칠살의 결단", "천마", "염정과 파군"이 그대로 노출됐습니다.

### 2-2. 사용자 목소리

- 리뷰(인생 운세): ★2 "지나치게 겉핥기 식이고 좋은 말만 써놔서 신뢰하기 어려움", ★1 "에바....."
- 추가 질문 31건(인생 운세, 관련 있음으로 분류된 것)의 유형:

| 유형             | 건수  | 예                                                                                            |
| ---------------- | ----- | --------------------------------------------------------------------------------------------- |
| **시기**         | 약 12 | 결혼 적령기는 언제야(×5), 몇 월에 취업(×3), 이직 시기, 독립 시기                              |
| **직업 분야**    | 약 6  | 무슨 직업, 기획 중 어떤 직무, 이전 재직 분야 맞혀봐                                           |
| **상대(배우자)** | 약 5  | 배우자 특징·외모·배경, 어떤 사람을 만날까                                                     |
| **반박/검증**    | 1     | "20대 초반이 좋다고 나왔는데 24살까지 죽고 싶을 만큼 힘들었다. 맞는 것도 있고 아닌 것도 있다" |

→ 본편은 "어떤 사람인가(성향)"와 "어떻게 살면 좋은가(조언)"에 답하고, 사용자는 **"언제, 누구, 무엇"**을 묻습니다. 추가 질문이 본편의 빈 곳을 메우는 데 쓰이고 있습니다.

> 표본 한계: 리뷰 2건, 추가 질문 31건은 통계가 아니라 방향 신호입니다. 2-1의 정량 측정(n=97)이 주 근거입니다.

## 3. 원인 진단 (기여도 순)

### ① 입력에 '이 사람만의 신호'가 없다 — 가장 큰 원인

- LLM 입력(`libs/services/ai/ziwei-interpreter.ts` `formatChartDataForAI`)은 "어느 궁에 어느 별이 있다"는 원자료의 나열입니다. 무엇이 특이하고, 무엇을 말하고, 무엇을 버릴지에 대한 우선순위가 없습니다.
- **엔진이 계산해 놓고 버리는 정보**:
  - 궁간(宮干): 어댑터가 `stem: 0`으로 덮어씁니다(`ziwei-interpreter.ts:307`). 궁간 사화(비행사화)를 계산할 재료가 사라집니다.
  - 신궁: `isShenGong: false`로 고정됩니다(`:317`).
  - 공궁 차성: 엔진에 `borrowedMainStars`(`calculators/empty-palace.ts`)가 있는데, 요약에는 "주성 없음"으로 나갑니다(`:339-341`).
  - 대운 점수: 엔진이 계산하지만 티어 단어로 바꾼 뒤 "노출 금지"로 넘깁니다(`:320-327`, `:474-482`).
  - 별 × 밝기 × 6축 성향 데이터(`constants/star-traits.ts`)는 궁합용으로만 연결돼 있습니다.
  - 결정적 분석 모듈 `libs/zi-wei-dou-shu/interpreter/{analyzer,summary,templates}.ts`는 어디서도 import되지 않습니다.
- **새로 계산해야 하는 것**: 궁간 비행사화, 자화(自化), 래인궁, 대운 사화가 원국의 어느 궁을 치는지(쌍기·록이 기를 푸는지 등), 협궁, 보좌·살성 조합 전체.
- 지금 입력으로는 명궁 주성 조합 기준 수십 개 유형이 개인화의 상한입니다(자미두수 전문가 추정, 전수 집계로 검증 필요).

### ② 해석 지식이 얕아서 모델이 사전지식 평균으로 메운다

- 프롬프트 속 지식은 별당 키워드 4개(`prompts/ko.ts:64-80`), 동궁 11쌍(`:100-112`), 사화 한 줄(`:138`)이 전부입니다. "천기가 재물 자리에 있으면 어떤가" 같은 궁위별 의미가 없습니다.
- 모델은 이 빈칸을 범용 자기계발 어휘로 채웁니다 → "기록" 91%, "분리" 60%.

### ③ 규칙이 많고 서로 충돌한다

- **용어 전면 금지(`:10-13`) vs "모든 문장에 데이터 근거 2개 이상"(`:45`)**: 근거를 보여줄 수 없는데 근거를 요구합니다. 사용자는 '왜'를 볼 수 없으니 "좋은 말만"으로 읽고, 모델은 충돌 속에서 결국 별 이름을 흘리기도 합니다.
- **"긍정 뒤엔 조건, 부정 뒤엔 대처법" 강제(`:48-51`, `:289-292`, `:323`)**: 모든 문장이 같은 2박자 구조가 됩니다 → oneLiner "~하되, ~하면 길이 열린다".
- **유형 라벨 금지, 근거 없는 진로 추천 금지(`:53`, `:407-410`), 연애 단순 판정 금지(`:461-464`)**: 사용자가 가장 묻는 '직업 분야·시기·상대'를 구조적으로 막습니다. 남는 건 행동 습관 조언뿐입니다.
- "다른 사람에게도 쓸 수 있으면 삭제하라"는 자기검증(`:20`)은 다른 사람의 출력을 볼 수 없는 모델에게 작동하지 않습니다.

### ④ 분량이 구체 장면을 막는다

- subSection body 60~100자, 한 문장 50자 이내(`:147`, `:194`). "무엇이 + 언제 + 왜 + 행동" 중 하나만 들어갑니다. ①~③의 효과를 키우는 증폭 요인입니다.

### ⑤ 점수를 LLM이 만든다

- 4영역 `score`를 모델이 0~100으로 직접 냅니다. 기준점이 없고 서비스 톤이 긍정적이라 80대에 몰립니다. 관상스포 선례(06~08)에서도 점수 편차는 프롬프트 패치로 고쳐지지 않았고 산식을 바꿔야 했습니다.
- 화면은 이 점수로 별점과 순위를 크게 보여줍니다. 점수 차가 1~3점이어도 순위는 만들어지므로 사실상 노이즈 순위입니다.

### ⑥ 8개 호출이 같은 prior에서 따로 뽑는다

- 섹션 간 중복 방지는 이전 headline과 첫 문장 80자만 전달합니다(`:712-756`). 어휘 수렴은 막지 못하고, 병렬 단계끼리는 서로의 출력을 못 봅니다.

### ⑦ 모델·temperature — 기여도 낮음

- gpt-5.4-mini, temperature 0.8. 관상스포 선례(09)에서 모델 교체는 밀도를 올렸지만 동질화는 그대로였습니다. **우선순위가 아닙니다.**

### ⑧ 출력 검증이 없다

- 인생 운세 경로(`ziwei-interpreter.ts`, `app/api/interpret/route.ts`)에는 zod 형식 검증만 있고 금지어·구조 검증이 없습니다. 별 이름 노출이 그대로 DB와 화면에 갔습니다.

## 4. 개선 설계

### 4-1. 생성 아키텍처: 사실 시트 → 서술 → 검증

```
명반 계산(기존)
   │
   ▼
[A] 해석 사실층 (엔진, 결정적, 신규)
   - 비행사화·자화·래인궁·차성·협궁·대운↔원국 상호작용 계산
   - 지식 룰 테이블에서 이 명반에 적중한 셀만 조회
   - 섹션별 '주장 후보' 3~5개를 랭킹해 사실 시트 생성
   - 4영역 점수, 시기 후보(연도/대운) 결정
   │
   ▼
[B] 서술 (LLM, 섹션별 호출)
   - 자기 섹션에 배정된 주장만 받아 문장으로 옮김
   - 시트에 없는 시기·직업명·수치는 쓸 수 없음
   │
   ▼
[C] 검증 (규칙 기반, 신규)
   - 위반 섹션만 재생성(최대 1~2회)
```

**[A] 사실 시트 항목 형태 (예)**

```ts
interface FortuneClaim {
  id: string; // 섹션 간 중복 배정 방지용
  section: "core" | "wealth" | "career" | "relationship" | "health" | "timing";
  topic: string; // 쉬운 말 주제: "편안함을 추구하는 쪽에 긴장이 걸림"
  evidence: ClaimEvidence[]; // 별·궁·사화·밝기 (LLM에는 숨기고 UI 근거 노출에 사용)
  strength: 1 | 2 | 3 | 4 | 5;
  direction: "positive" | "negative" | "mixed";
  period?: string; // "26-35세" 또는 "2027년"
  sceneSeeds: string[]; // 룰 테이블의 구체 장면 문장 2~3개
}
```

- 랭킹 기준(초안): 사화 위치 > 밝기 극단(묘·함) > 대운↔원국 상호작용 > 동궁·협궁 조합 > 격국 > 일반 주성. **흔한 조합일수록 가중치를 낮춥니다**(전체 사용자 분포 대비 희소성).
- 섹션마다 주장 ID를 겹치지 않게 배정합니다. 재물에 쓴 주장은 직업에서 못 씁니다. 그러면 ⑥의 공유 prior 문제가 구조적으로 풀립니다.

**지식 룰 테이블 (사람이 쓰고 ziwei-expert가 검수)**

| 테이블                                                    | 규모(추정)    | 비고                                                   |
| --------------------------------------------------------- | ------------- | ------------------------------------------------------ |
| 주성 × 밝기 3단계 × 핵심 6궁(명·재백·관록·부처·질액·복덕) | 252셀         | `star-traits.ts`의 3단계 밝기 구조 재활용              |
| 사화 4종 × 12궁                                           | 48셀          | 1순위 착수                                             |
| 주성 직업군 매핑                                          | 14행          | 예: 천기=기획·분석·IT, 거문=언어·법률·교육 (전통 매핑) |
| 실제 동궁 쌍성 조합                                       | 약 30쌍       | 현재 11쌍                                              |
| 보좌·살성 × 궁위                                          | 약 15성 × 6궁 |                                                        |
| 비행사화 해석 규칙                                        | 약 20개       | 유파 기준(삼합파) 검수 필요                            |

→ 프롬프트에는 전체 표를 붙이지 않고 **적중 셀만** 넣습니다. 호출당 수백~천 자면 충분하고, 지금의 공통 지식 블록보다 입력이 줄어듭니다.

**[C] 검증기 (ai-dev 제안)**

1. 금지 용어 정규식(별·궁·사화·격국·유형 라벨·디스클레이머)
2. 시트에 없는 시기·숫자·직업명
3. headline이 최근 N건 캐시와 n-gram 유사도 과다
4. 종결 패턴 반복 상한("~하면 길이", "~하되")

블랙리스트 어휘를 계속 늘리는 방식은 관상스포에서 두더지 잡기였습니다(07 §3.3). **구조 지표 중심**으로 둡니다.

### 4-2. 점수 결정화

- 4영역 점수는 엔진이 산출합니다: 해당 궁 별 강도 + 밝기 + 삼방사정 + 사화(+/−) 가중합을 **전체 사용자 분포 기준 백분위로 정규화**합니다(관상스포 06 옵션 D).
- 응답 스키마에서 `score`를 뺍니다. LLM에는 방향만 넘깁니다.
- 변별력이 생기기 전까지 화면의 순위 노출은 "4영역 중 가장 강한/약한 영역"처럼 상대 비교로 축소합니다.

### 4-3. 콘텐츠 구조

| 변경                                      | 내용                                                                                                                                           | 겨냥하는 근거                                                                                              |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **추가: 지난 시기 확인 컷** (예고편 무료) | 이미 지난 대운 1~2개에 대해 확인할 수 있는 진술 2~3개 + "맞아요/아니에요" 탭                                                                   | 신뢰는 '맞혔다'는 경험에서 생김. 반박 사례처럼 사용자가 이미 검증을 시도함. 응답은 품질 피드백 데이터가 됨 |
| **추가: 타이밍 섹션** (본편)              | 결혼·연애 / 취업·이직 / 이동 후보 시기를 대운 + 연도 단위로. "가능성이 높은 해 / 조심할 해"                                                    | 추가 질문 1위(시기 약 12건)                                                                                |
| **추가: 근거 한 줄**                      | 각 영역에 쉬운 말로 번역한 근거 1줄("재물을 보는 자리에 계산이 빠른 별이 앉아 있어요")                                                         | ★2 "신뢰하기 어려움", 용어 금지 vs 근거 요구 모순 해소                                                     |
| **추가: 상대 묘사** (인연)                | 만날 사람의 성향·역할·만나는 경로. **외모·직업 단정은 하지 않음**(전통에서도 근거가 약함)                                                      | 배우자 질문 약 5건                                                                                         |
| **변경: 직업 분야 허용**                  | 엔진이 만든 직업군 후보 안에서만 분야명 제시                                                                                                   | 직업 분야 질문 약 6건                                                                                      |
| **통합**                                  | 스포일러·핵심 시나리오·성향이 모두 '성향+조언'을 반복함 → "나의 한 줄 + 근거 + 확인 컷"으로 압축하고, 아낀 분량을 영역별 시기·대상·장면에 배분 | 섹션 간 중복                                                                                               |
| **분량**                                  | body 60~100자 → 120~200자 또는 항목 수를 줄여 깊이로                                                                                           | ④                                                                                                          |

**미리보기(결제 동기)**: 확인 컷 하나를 열어 보여주고, 잠긴 부분은 "결혼 시기: 후보 3개 중 첫 번째 ●●●"처럼 **질문 유형을 라벨로 노출**합니다(내용은 가림). 빈 곳이 구체적일수록 궁금증이 커진다는 일반 원리에 근거한 가설이며, A/B로 확인합니다.

**공유할 한 문장**: 성향 한 줄에서만 한쪽으로 기운 단정을 허용합니다("결정은 빠른데 시작은 느려요"). 시기·건강·돈은 가능성 표현을 유지합니다.

### 4-4. 프롬프트 규칙 재설계

- **삭제**: "긍정 뒤 조건 / 부정 뒤 대처" 강제, 모델이 할 수 없는 자기검증 지시, 공통 지식 표(룰 테이블 조회로 대체).
- **변경**: 시트의 방향(+/−)대로 씁니다. 좋은 건 좋게, 나쁜 건 나쁘게 쓰되 시트에 나쁜 항목이 있을 때만 씁니다.
- **완화**: 시기·직업 분야·상대 성향은 **시트에 근거가 있을 때 허용**하고, 시트에 없는 것은 금지합니다.
- **유지**: 적중률 보장 금지, 의료·투자 단정 금지, 디스클레이머·메타 잡소리 금지, 존댓말.
- 모든 항목에 장면 시드 1개 이상을 인용하게 합니다.

## 7. 대표 결정이 필요한 사항

1. **근거 용어 노출 수준**: 브랜드 보이스는 CTA 문장에서만 전문 용어를 막고, `docs/brand/voice-guide.md` 예시는 오히려 "재물궁에 천기성이 앉아있거든"을 권장합니다. 반면 해석 프롬프트는 전면 금지입니다. 선택지는 (a) 쉬운 말 근거만, (b) 별 이름까지 쉬운 설명과 함께 노출, (c) 현행 유지입니다. **권장: (a)로 시작해 확인 컷 반응을 보고 (b) 검토.**
2. **시기 예측의 표현 한계**: "가능성이 높은 해"까지 허용할지. 법적 주의(적중률 보장 금지)는 유지됩니다.
3. **기존 결제 사용자 재생성 여부**: 개선 후 기존 3,455건에 재생성을 제공할지(비용 vs 리뷰 회복).
4. **우선순위**: Phase 1(빠른 개선)을 먼저 낼지, Phase 0~2를 묶어서 낼지.

## 8. 미확인·한계

- 명궁 주성 기준 유형 수(30~40종)는 자미두수 전문가의 추정입니다. 엔진으로 전수 집계해 검증해야 합니다.
- 비행사화·시기 판정 규칙은 유파마다 세부가 다릅니다. 구현 전에 삼합파 기준 검수가 필요합니다.
- 룰 테이블 분량, 점수 표준편차 목표, 비용 수치는 추정치입니다.
- 포러 효과(Forer, 1949: 모호한 성격 기술에 대한 평균 일치도 약 4.3/5) 외 심리학 근거는 일반 원리 수준입니다. 외부에 인용하려면 원문 확인이 필요합니다.
- 예고편·본편의 잠금 경계는 코드로 끝까지 확인하지 않았습니다.

## 10. Phase 2~3 구현 현황 (2026-11-06, 같은 PR)

### 10-1. 결정 사항

- Phase 1~3을 한 브랜치(PR #223)에서 진행.
- 근거 한 줄은 **쉬운 말만** (별 이름·사화 용어 노출 없음).
- 타이밍은 **"가능성이 높은 해"(연도 단위)** 까지만. 월·날짜는 말하지 않음.
- 과거 시기 "맞아요/아니에요" 확인은 **넣지 않음** — 명반 풀이를 사용자 답으로 고치면 신뢰가 떨어진다는 판단. 그래서 DB 테이블 추가 없음.

### 10-2. 엔진 (사실 시트)

- `libs/zi-wei-dou-shu/constants/lifetime-facts/`: 생년 사화×궁 48칸, 주성별 직업 분야 14행, 쌍성 24쌍, 비행사화 22규칙, 배우자상 14행 (자미두수 전문가 작성).
- `libs/zi-wei-dou-shu/calculators/lifetime-facts.ts`: 명반에서 해당 규칙을 골라 섹션별 주장(claim)으로 배정. 섹션당 주장이 2개 미만이면 기본 별 설명으로 보충.
- **근거 한 줄 규칙**: 생년 사화는 그 영역의 궁(재백·관록·부처·질액)에 걸렸을 때만, 비행사화는 규칙에 지정된 영역에만 근거로 씀. 쌍성·기본 별 설명은 성격 문구라 영역 근거로 쓰지 않음. 직업·인연은 각각 직업 분야표·배우자상표 근거로 보충.
- **타이밍**: 향후 10년(올해+1 ~ +10) 유년 사화가 해당 궁에 들어오는 정도로 점수(록 3·권 2·과 1.5·기 −3.5, 유년 지지=궁 지지 +2, 대운 사화 ×0.5). 주제(연애·일·이사)별 상위 3개 해와 조심할 해 1개.
- 대운 천간 버그 수정: 대운 궁의 궁간을 그대로 사용 (`dayun.ts`).
