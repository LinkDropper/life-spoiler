홈 프로필 셀렉트 시안

정책 변경: 홈에 프로필이 이미 선택돼 있고, 운세를 누르면 /profiles를 거치지 않고 바로 운세로 간다. 첫 프로필이 기본값이며 화면에 "본인/나" 표시는 없다. 375px 모바일 정적 시안, 코드 변경 없음. 홈 본체는 home-v4/c.html(현재 코드와 같은 구성)을 그대로 쓰고 시트는 common-sheets/02 문법을 발전시켰다.

선택한 안 요약

  • 위치: 헤더 바로 아래, 오늘의 운세 배너 위. 화면 맨 위에 두면 "아래 모든 운세가 이 사람 기준"이라는 읽기 순서가 맞다.
  • 트리거: 면 하나(테두리·글로우 없음) 안에 "민지님의 스포일러" + 생년월일 한 줄 + 오른쪽 화살표(44px). 프로필이 1개든 여러 개든 같은 모양이다.
  • 열림: 바텀시트로 확정. 마지막 줄 "프로필 추가".
  • 0개: 셀렉트 자리에 "먼저 프로필을 만들어요 [만들기]" 한 줄. 운세 칸은 막지 않고, 누르면 그 운세 이름이 붙은 프로필 입력으로 이어져 만들자마자 그 운세를 본다.

1. 닫힌 상태 트리거

프로필 개수와 상관없이 트리거 모양은 같다. 1개일 때도 화살표를 지우지 않는 이유는 펼쳐야 "프로필 추가"에 닿을 수 있기 때문이다. 이름이 길면 이름만 말줄임, "님의 스포일러"는 줄바꿈 없이 고정한다.

2. 열린 상태 바텀시트 확정

바텀시트로 확정했다. 이유: (1) 한 손 엄지가 닿는 아래쪽이고 행이 56~68px라 터치 타겟이 넉넉하다. (2) 프로필이 5~6개로 늘거나 EN/JA 이름이 길어져도 시트 안에서 스크롤하면 되고, 드롭다운처럼 화면 밖으로 밀리지 않는다. (3) 언어·프로필 전환 등 앱의 다른 시트(common-sheets)와 같은 문법이라 새 패턴이 늘지 않는다. 앵커 드롭다운 안은 트리거가 화면 위쪽이라 엄지 거리가 멀고, 목록이 길어지면 오늘의 운세 배너를 덮어서 제외했다.

3. 프로필 0개 신규 유저

셀렉트가 비어 있으면 "아무도 없음"이라는 빈 셀렉트를 보이지 않고, 같은 자리에 시작 유도 한 줄을 둔다. 운세 칸을 막으면(비활성) 첫 방문에서 아무 곳도 못 누르는 막힘이 되므로, 어느 칸을 눌러도 프로필 입력으로 가고 완료하면 누른 운세로 곧장 이어진다. 오늘의 운세는 지금도 프로필 1개면 선택 화면을 건너뛰는 흐름이라 같은 감각이다.

4. 어떤 프로필로 보는지 헷갈리지 않게 맥락 문구

  • "○○님의 스포일러"를 트리거 자체의 문구로 쓴다. 별도 라벨("선택된 프로필" 등)이 없어도 문장이 곧 상태다. 서비스 용어(스포일러)와도 맞고, "본인/나" 없이 이름만으로 구분된다.
  • 이 문장은 홈 맨 위에 있고 그 아래 진열장 전체가 그 사람 기준이라는 구조로 전달한다. 오늘의 운세 배너·진열장 각 칸에는 이름을 반복하지 않는다(중복 소음).
  • 결과 화면은 이미 프로필 이름을 보여 주고 있을 것이므로(코드 미확인) 거기서 한 번 더 확인된다. 홈에서 잘못 골랐을 때의 복구가 이 두 겹이다.
  • EN Spoilers for [name], JA [name]さんのスポイラー. 번역 키는 앞·이름·뒤를 분리하거나 이름만 말줄임 처리할 수 있어야 한다(구현 메모).

5. 궁합 · 관상과의 관계 메모

운세셀렉트와의 관계
오늘·인생·올해·내년·전생선택된 프로필 1명으로 바로 진입한다. 이번 정책의 대상.
궁합두 사람이 필요하다. 홈 셀렉트의 프로필이 첫 번째 칸의 기본값으로 미리 채워지고(바꿀 수 있음), 두 번째만 새로 고른다. 흐름은 08 참고. 진열장의 궁합 칸은 지금처럼 /compatibility로 간다.
관상사진 기반이라 별도 프로필 흐름(/face-spoiler/profiles)이다. 홈 셀렉트와 연결하지 않는다. 프로필을 바꿔도 관상 칸의 동작은 변하지 않으므로 사용자가 "관상도 민지 기준"이라고 오해할 수 있는지가 관건(미결 질문 참고).
나만의 별자리(친구 우주)링크 공유형 흐름이라 셀렉트와 무관.

6. 결제 상태 A 조명 확정

왼쪽 민지(인생·올해 결제), 오른쪽 서연(결제 없음). 결제 안 한 칸은 원래 모습 그대로다.

접근성 · 구현 메모

  • 트리거는 button + aria-haspopup="dialog", aria-expanded. 레이블에 현재 이름과 생년월일을 읽어 준다. 시트는 role="dialog" + 안쪽 listbox/option(aria-selected), "프로필 추가"는 listbox 밖의 button.
  • 모든 행 최소 56px, 트리거 64px, 화살표/닫기 44px. 보조 글씨 #aeabbd는 트리거 면 위에서 4.5:1 이상(계산 추정, 기기 확인 전).
  • 한국어는 :lang(ko)에만 word-break: keep-all. 긴 이름은 트리거에서 말줄임, 시트 행에서는 overflow-wrap:anywhere.
  • 시트 열림 중 뒤 화면 스크롤 잠금, 닫으면 포커스는 트리거로 복귀. 시트가 프로필 6개 이상이면 목록만 스크롤(시안은 3개).
  • 이미지·스타일은 ../home-v4/img와 home.css 상대 경로. 폰트만 jsdelivr(Pretendard) 외부 로딩이다. 브라우저 렌더링은 확인하지 못했고 코드로만 검토했다.

확정된 정책

  • 선택 유지: 재방문 시 직전 선택을 유지한다(기기 로컬 저장). 저장값이 없거나 그 프로필이 삭제됐으면 첫 프로필(created_at이 가장 이른 것)로 돌아간다. 기존 다중 프로필 유저도 같은 규칙.
  • 삭제 위치: /profiles 화면은 없앤다. 삭제는 바텀시트 우상단 "편집"에서 한다(03b → 03c).
    • 선택 중인 프로필을 삭제하면 홈 트리거가 첫 프로필로 돌아간다. 확인 시트에 "삭제 후 홈: 서연님의 스포일러" 줄로 미리 알린다.
    • 마지막 1개를 삭제하면 0개 상태(04)로 간다. 이때 확인 시트의 "삭제 후 홈" 줄은 "프로필 만들기 화면"처럼 바꿔 쓴다.
  • 신규 유저: 0개여도 홈부터 보여 준다(04, 05 그대로).
  • 개수 제한 없음. 목록이 길어지면 시트 안에서 목록만 스크롤한다. 예외 계정(RESTRICTED_USER_ID)은 유지하며 시트에서 "프로필 추가"와 "편집"을 숨긴다(03d).

미결 질문

  • 첫 프로필이 본인이 아닌 경우: 가족을 먼저 만든 유저는 기본 선택이 본인이 아니다. "본인" 표시를 두지 않기로 했으므로 구분 수단은 이름뿐이다. 이를 허용하고 지켜볼지, 입력 단계에서 안내할지.
  • 관상 오해 방지: 셀렉트를 바꿔도 관상은 별도 흐름이라는 것을 문구로 알릴지, 현재 부제("사진 한 장으로")로 충분한지.
