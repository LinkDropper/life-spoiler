# 결제 흐름(매표소 → 발권) 시안 v3

375px 모바일 기준 정적 HTML. 코드(app/, components/)는 건드리지 않았고, 시안 확정 뒤 구현한다. `SB-B.otf`와 같은 폴더에서 열어야 디스플레이 폰트가 나온다.

v3은 대표 피드백("선택 border가 AI스럽다, AI 디자인 같은 것을 걷어내라")을 반영해 01~03, 06~08을 다시 그렸다. 04, 05는 출시된 `ScreeningOverlay` 재현이라 그대로다.

## 디자인 결정 근거

1. **문법은 승인된 화면을 따른다.** 친구 시사회 `self.html`과 홈 시간표처럼 박스 없이 얇은 구분선으로 나뉜 목록 행, 평평한 관람권 종이, 디스플레이 서체 제목만 쓴다.
2. **효과를 전부 뺐다.** 글로우, text-shadow, drop-shadow, 스포트라이트 그라데이션, 원 배지, 진행 막대, 박스 카드를 쓰지 않는다. 남은 것은 면, 얇은 선, 글자 굵기뿐이다.
3. **매표소 슬롯은 형태로만 남겼다.** 어두운 얇은 막대(슬롯)와 그 아래 나온 관람권이다. 상태별로 위치만 다르다.
   - 결제 전: 관람권이 슬롯에 반쯤 꽂혀 있다 (01~03)
   - 완료: 관람권이 밖으로 나오고 꼬리표가 떨어져 있다 (06)
   - 승인 실패: 윤곽선만 남은 빈 관람권 (07)
   - 실패·취소: 슬롯에 그대로 꽂혀 있고 종이만 한 톤 어둡다 (08)
4. **위계는 관람권 한 장에 있다.** 상품명, 관객, 혜택, 열람 기간, 금액이 관람권에 모인다. 하단 바의 금액은 20px 굵은 본문 서체로 낮췄고, 디스플레이 서체는 제목에만 쓴다.
5. **결제 수단은 목록 행이다.** 선택은 글씨가 굵고 흰색이 되며, 오른쪽에 핑크 체크 표시 하나가 나온다. 테두리·채움·링은 없다. 마크업은 실제 `radio`이고 `fieldset/legend`로 묶었다. 쿠폰도 같은 행 하나이며, 고르면 아래에 들여 쓴 보유 쿠폰 목록과 입력란이 이어진다.
6. **색은 역할대로만 쓴다.** 채움(버튼)은 연핑크, 선택 표시는 핑크, 포커스는 금색이다. 가격 강조나 장식에는 쓰지 않는다. 오류 색 원 배지도 없앴고, 오류는 제목 문구로만 전달한다.

## 실제 구현할 때 바뀌는 점

- **결제 수단 순서:** 현재 코드는 카카오페이, Apple Pay, 토스페이, 카드, 쿠폰이다. 시안은 Apple Pay를 간편결제 마지막으로 내렸다. 목록 행이라 지원하지 않는 기기에서 빠져도 레이아웃이 깨지지 않는다.
- **하단 버튼 문구:** 지금은 `payButtonSimple`이 "990원 결제하기"로 고정이라 이벤트 가격이 반영되지 않는다. 시안은 금액을 바에 따로 두고 버튼을 "결제하기"로 줄였다. 번역 키 변경이 필요하다.
- **쿠폰 목록:** 현재 코드는 쿠폰 적용 후 보유 쿠폰이 사라진다. 시안은 적용된 쿠폰에 체크를 남기고 나머지는 비활성으로 둔다. 선택은 `radiogroup` 의미를 가진다.
- **쿠폰 미적용 상태:** 시안에 없다. 쿠폰 행만 골랐을 때 버튼은 지금처럼 비활성이고, 바의 금액은 정가 그대로다.
- **쿠폰 오류 토스트:** 시안은 성공 토스트만 보여 준다. 오류는 같은 면 토스트에 문구만 바꾸고 `role="alert"`로 쓴다. 3초 뒤 자동으로 사라진다.
- **궁합:** 관람권 "관객" 줄이 `지수 × 민준`처럼 두 사람이 된다. 길면 줄바꿈된다.
- **해외 로케일:** 가격은 `$0.99`, 결제 수단은 PayPal 행과 쿠폰 행이다. 첫 결제 이벤트는 KRW 전용이라 02 상태는 없다.
- **08 화면의 상품명:** 현재 fail 페이지는 에러 코드만 보여 준다. 관람권 요약은 쿼리의 `fortuneType`으로 상품명을 만들고 이름은 프로필 스토어에서 읽어야 한다. 읽지 못하면 관람권 없이 에러 코드만 보여 주는 것으로 낮춘다.
- **06 화면의 금액:** 이벤트 가격이나 0원이어도 승인 응답 값을 그대로 표기한다.
- **번역 키:** 새 문구(관람권 · 본편, 관객, 혜택, 열람 기간, 발권 전, 상태 등)는 KO/EN/JA를 모두 추가해야 한다.
- **로딩 04, 05:** 새 구현이 필요 없다. 기존 `PaymentScreeningLoading`을 그대로 쓴다.
- **스크린리더:** 결제 완료는 `role="status"`, 실패·취소는 `role="alert"`로 제목을 감쌌다.

## v2에서 제거한 것

연핑크 통채움·두꺼운 선택 테두리·글로우 링·원 안 체크, 타일 위 보조 라벨, 쿠폰 점선 타일과 아이콘, 모든 글로우·그림자 효과, 원 배지(금색 체크·빨간 느낌표), 1·2·3 진행 막대, 에러 코드·쿠폰·토스트의 테두리 박스, 대형 디스플레이 숫자.

## 한계

- 하단 바에서 취소선 금액 + 20px 금액 + 버튼이 375px에 들어가는지
