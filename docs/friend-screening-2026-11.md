## 1. 컨셉: "친구 시사회"

**내 인생 영화의 시사회에 친구를 초대하고, 친구는 초대장을 받아 입장해 자기 자리(궁합)를 확인한다.**

- 받는 쪽이 "표를 받았다"로 이해한다 → 링크를 열 이유가 생긴다(growth).
- 홈 관람권·프로필 관람권·로그인 좌석 배치도와 같은 장치를 재사용한다(신규 장치 비용 낮음, designer).
- 결과는 **엔딩 크레딧**으로 보여 준다. 데이터의 본체가 점수순 목록이라, 목록이 곧 메인 UI이자 접근성 대체 구조가 된다(designer·planner).
- 별 시각화는 버리지 않고 **스크린 속 밤하늘**로 옮긴다. 저장 좌표(`posXRatio/posYRatio`)를 그대로 쓰므로 "내 자리"가 매번 바뀌지 않는다.
- 캐스팅(주연·조연) 메타포는 쓰지 않는다. 낮은 점수가 역할 위계로 읽혀 모욕감 위험(growth).

## 2. 요소 매핑 (데이터 → 새 장치)

| 기존 | 새 장치 | 쓰는 데이터 |
| --- | --- | --- |
| ① owner 요약 카드 | **타이틀 카드**: 필름 칸 안 밤하늘(`NightSkyArt`, 시드=publicId) + 큰 h1 "지수님의 시사회" + owner 한줄평을 화면 자막으로 + 상영 안내 행(관객 N명 \| 전체 128번째로 붐비는 시사회) | ownerName, oneLinerKo, guestCount, guestCountRank, confidence |
| ② 입력 폼 | **초대장 관람권**(가로 티켓, 절취선) 위에 "초대받은 관객 정보" → 버튼 "내 자리 확인하기" | 입력은 기존 POST 그대로 |
| ② 내 궁합 카드 | **내 관람권**: 좌석 대신 점수(큰 숫자) + 등급 + 한줄평 자막 + 근거(상영 안내 행 형식). 확인 순간 꼬리표 찢김(NextTicket 동작 재사용, 1회) | selfGuest / 제출 결과, factors |
| ③ 별 시각화 | **스크린**: 위쪽 곡선 스크린(로그인 SCREEN과 같은 문법) 안 밤하늘. 주최자 별은 중앙, 관객은 저장 좌표에 작은 빛점 + 이름. 크기·밝기 = 기존 `getStarVisual(score)` 그대로. 상시 모션 제거, 입장 시 1회 점등 | posX/posYRatio, score, name, starSeed |
| ③ 30명 초과 | 상위 30만 빛점, 나머지는 "외 N명은 크레딧에" 표시. 내가 30위 밖이면 스크린 오른쪽 아래 고정 자리 | 기존 규칙 유지 |
| ④ 궁합 순위 | **엔딩 크레딧**: 1~3위 "주요 관객"(핑크 계열, 금은동 메달 제거), 4위부터 크레딧 줄. 행 = 순위·이름·점수(첫 줄) / 한줄평(둘째 줄). 탭하면 기존 드로어 | guests[] |
| ⑤ 다른 운세 보기 | 첫 줄을 **"이번엔 내 시사회 열기 (무료)"** 큰 외곽선 버튼으로, 그 아래 유료 운세는 홈과 같은 **상영 시간표** 행 형식 | 정적 |
| ⑥ 공유 | **초대장 보내기**: 작은 초대장 티켓 + "초대장 보내기" 버튼 | 기존 Web Share/복사 |
| 생성 화면 | **시사회 열기**: 상단에 빈 스크린 + "내 인생 영화 시사회를 열어요", 폼은 프로필 만들기(StepOne)와 같은 문법 | 입력 기존 그대로 |

영역 순서 ①~⑥은 그대로 둔다(CPO 확정). ⑤ 안의 순서만 바꾼다.

## 2-1. v2 수정 (2026-11-04 사용자 피드백): 별 → 좌석 배치도

> 피드백: "시사회인데 여전히 별자리처럼 만들면 어쩌냐. 로그인 화면처럼 자리 배치도에 친구들이 앉고, 점수가 클수록 스크린에 가깝게."

**위 2절의 ③ 스크린 밤하늘·필름 칸 밤하늘은 폐기한다.** 친구 시사회 화면 어디에도 별·밤하늘·성운을 쓰지 않는다.

**좌석 배치 규칙** (로그인 `SeatMap`과 같은 문법, 6열 × 9석)

| 열 | 점수 구간 (= 기존 등급 구간, 엔진 상수 그대로) |
| --- | --- |
| A (스크린 바로 앞) | 90점 이상 |
| B | 78~89 |
| C | 66~77 |
| D | 54~65 |
| E | 42~53 |
| F (맨 뒤) | 41 이하 |

- 점수가 높을수록 스크린에 가깝다. 열이 곧 등급이므로 등급 라벨(쌍성 등)은 화면에 쓰지 않는다(5절 2번 자연 해소).
- 한 열 안에서는 점수 높은 사람부터 **가운데 자리(5번)에서 바깥으로** 채운다: 5 → 4 → 6 → 3 → 7 → 2 → 8 → 1 → 9. 동점은 목록 순서.
- 한 열에 9명을 넘으면 맨 바깥 자리를 "+N" 표시로 바꾼다. **내 자리는 항상 보인다**(넘치면 마지막 보이는 자리를 내가 차지하고 "+N"은 그 옆 바깥으로).
- 좌석 안에는 이름 첫 글자, 내 자리는 핑크 채움 + 아래에 "내 자리 · D5"(로그인과 같은 형식). 빈 자리는 로그인과 같은 어두운 칸.
- **열 단위로 누른다**(2026-11-04 사용자 결정). 좌석 칸(30×26px)은 44px 터치 기준에 못 미치므로, 관객이 있는 열 전체(높이 44px)가 링크다. 누르면 엔딩 크레딧에서 그 열의 첫 관객으로 이동한다. 빈 열은 누를 수 없다. 접근 가능한 목록은 크레딧이 맡는다.
- **엔딩 크레딧은 5명까지만**(2026-11-04 사용자 결정). 1~5위만 보이고 나머지는 "관객 N명 더보기"로 펼친다. 내 행이 6위 밖이면 점선 구분 뒤에 함께 보인다(내 결과는 접지 않음). 열을 눌렀는데 그 열 관객이 접혀 있으면 자동으로 펼치고 이동한다.
- 주최자는 좌석에 앉지 않는다. **스크린 자체가 주최자의 상영작**이다: 곡선 스크린 위에 "지수님의 시사회", 그 아래 한줄평 자막.
- 기존 30개 렌더 상한은 열별 9석 상한(최대 54석 노출)으로 바뀐다. "외 N명"은 열별 "+N"으로 대체.

**데이터 영향**: 저장 좌표(`posXRatio/posYRatio`)는 이 화면에서 쓰지 않는다. DB·API 변경 없음. 대신 같은 열에 새 친구가 들어오면 그 열 안에서 좌석 번호가 밀릴 수 있다(열은 점수로 고정이라 바뀌지 않음).

**영역 순서 변경 제안**: 스크린과 좌석이 떨어져 있으면 극장으로 읽히지 않으므로 ①(타이틀)과 ③(시각화)을 합쳐 맨 위에 둔다: **① 스크린 + 좌석 배치도 → ② 초대장 폼 / 내 관람권 → ④ 크레딧 → ⑤ → ⑥.** CPO 확정 순서를 바꾸는 것이므로 확인 필요.

## 3. 시각 규칙

- 배경 단색 `--cinema-night #0c1220`. 보라 그라데이션·CSS 성운 제거.

- 375px 우선, 터치 44px, `prefers-reduced-motion`에서 모든 연출 정지.

## 5. 결정이 필요한 것 (사용자/CPO)

1. **기능명**: "친구 시사회"(추천) vs "내 상영관".
2. **등급 라벨**: 엔진 라벨(쌍성·밝은 궤도·스치는 혜성 등)이 우주 어휘라 새 화면과 섞인다.
   - (a, 추천) UI에서 등급 라벨을 숨기고 점수 + 한줄평만 표시
   - (b) 클라이언트 표시용 라벨만 영화 어휘로 매핑(슬러그·구간은 그대로, 예: 쌍성 → 같은 장면)
   - (c) 그대로 노출
3. **OG 이미지**: 공용 이미지 유지 vs 초대장 티켓 정적 이미지 1장 추가(코드·DB 변경 없음, 권장).
4. **예전 이름 안내**: 상세 상단에 "구 친구 우주" 보조 문구를 2~4주 둘지.

## 6. 범위 밖 (이번에 하지 않음)

- owner 전용 화면: GET 응답에 owner 판별값이 없어 UI만으로 불가. owner 재방문도 입력 폼이 보이는 현재 동작 유지.
- 상영관 3D 전환(`isScreeningDestination`) 추가: 홈 기획의 제외 결정 유지.
- GA 이벤트 신설: 지금은 친구 우주 전용 이벤트가 없다. 효과를 비교하려면 **컨셉 반영 전에** `universe_create_submit`, `universe_share_click`, `universe_guest_submit`, `universe_loop_cta_click`을 먼저 심어 베이스라인을 쌓는 것을 권장(growth). 별도 작업으로 분리.
- 드로어 포커스 트랩·ESC 닫기 보강: 접근성 부채. 구현 단계에서 같이 처리 권장.
