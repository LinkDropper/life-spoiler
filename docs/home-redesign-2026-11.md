# 홈(로그인 후) 기획 v3 — 랜딩의 다음 장면, "지금 상영 중"

> 2026-11-03 | 상태: **기획 컨펌 대기 (구현 전)**
> 스킬: Anthropic `frontend-design`(skills.sh 1.1M, 랜딩에서 사용), Vercel `web-design-guidelines`(817.9K), Corey Haines `marketingskills`의 `onboarding` v2.0.2·`paywalls` v2.1.1
> 데이터: 운영 DB 읽기 전용 집계(2026-11-03, 개인 정보 미조회)

## 0. 왜 다시 하나

- v1("내 상영관", 포스터 카드): `frontend-design`이 꼽는 생성형 기본값(같은 카드 반복, 가운뎃점 eyebrow, `→`)이었고 배치를 데이터 없이 정했다.
- v2(레터박스 자막 + 텍스트 목록): 배치는 데이터로 정했지만 **랜딩의 시각 언어를 버려** 같은 제품으로 보이지 않았다(피드백: "랜딩과 톤 차이").
- v3 초안(장면 5개를 위아래로): 세계관은 맞췄지만 **매번 들어올 때마다 거칠 단계가 많다**(피드백). `onboarding`의 최소 경로(MPTV)·Hick's Law와도 어긋난다.
- v3 원칙: **컨셉은 랜딩과 같은 세계관, 요소는 모두 그 세계관의 장치, 그리고 자주 하는 행동은 첫 화면에서 한 번에.**

## 2. 컨셉: 랜딩이 끝난 자리에서 시작한다

랜딩은 밤하늘에서 시작해 새벽에 끝나고, 마지막 문장이 **"이제 당신의 본편을 상영할 시간이에요"**다. 인생 필름 장면은 "10년마다 한 장면씩"을 보여 주며 **"줄거리는 본편에서 공개돼요"**라고 잠가 두고, 눈금자에 **"지금 여기쯤"**을 찍는다.

홈은 그 본편이 **지금 상영 중인 화면**이다. 랜딩이 예시 인물의 필름을 틀었다면, 홈은 **내 필름의 지금 장면**을 띄운다.

| 랜딩의 장치                                                     | 홈에서                                           |
| --------------------------------------------------------------- | ------------------------------------------------ |
| 밤하늘 (첫 장면)                                                | 같은 CSS 밤하늘 배경                             |
| 인생 필름 한 칸 (구멍 띠, 가장자리 코드, 대운궁 색 별자리 스틸) | 히어로 = **내 필름의 지금 칸**                   |
| "줄거리는 본편에서 공개돼요"                                    | 소장자에겐 **지금 10년의 줄거리 한 줄**이 열린다 |
| "지금 여기쯤" 눈금자                                            | 내 대운 눈금자에 내 위치                         |
| 본편 관람권 (핑크 종이, 절취선)                                 | 다음 편 = **관람권**                             |
| 상영 안내 (라벨 \| 값, 핑크 가는 줄)                            | 모든 운세 = **상영 시간표**                      |

## 3. 화면 구성 — 3구역, 거쳐야 할 단계 0

**원칙**: 들어오자마자 할 일이 한 화면에 있다. 아래 세 가지는 375×812 첫 화면 안에서 **탭 한 번**으로 간다. 순서는 방문자 비중 순이다.

1. 내 본편 이어 보기 (소장자 72.8%)
2. 다음 편 보기 (두 번째 구매가 실제로 일어나는 곳, 대부분 올해 운세)
3. 오늘의 운세 (KO, 매일 다시 올 이유)

나머지 운세는 그 아래 시간표에서 고른다. 자동 연출은 **세션당 처음 한 번만** 재생하고, 같은 세션에 다시 오면 바로 보인다(재방문 화면이라 매번 기다리게 하지 않는다).

## 4. 시각 시스템 — 랜딩 토큰과 장치 그대로

- 토큰: 랜딩 `--cinema-*`(night `#0c1220`, spoiler `#ffccd9`, star `#ffe7a3`, haze, line, ink).
- 서체: SB 어그로(제목)와 Pretendard. JA는 Pretendard 800(SB 어그로에 한자 없음).
- 장치는 새로 그리지 않고 랜딩 것을 공용으로 옮겨 쓴다: 필름 프레임·스틸(`film-still.ts`, `PALACE_TINTS`), 눈금자, 관람권 모양, 상영 안내 행.
- `frontend-design` 점검: 대담한 곳은 히어로 필름 칸 하나. 금지 목록(가운뎃점 eyebrow, `→`, 같은 카드 반복, 섹션마다 fade-up)은 유지하되, 필름 가장자리 코드의 "▸"는 랜딩 원문 장치라 쓴다.

## 6. 구현 메모 (2026-11-03)

- **프로필 선택**: 기본은 처음 만든 프로필(`pickOwnProfile`). 프로필이 2개 이상이면 히어로 오른쪽 위에 "상영 중인 필름" 네이티브 셀렉트가 나온다(1개인 86%에겐 숨김). 고른 프로필은 `?profile=` URL에 남겨 새로고침·뒤로 가기에도 유지한다(`web-design-guidelines`: URL이 상태를 반영). 시간표·관람권 링크도 고른 프로필 기준이다.
- **필름 데이터**: 소장자는 구매 결과의 `dayun.periods` + `ageScenarios`(시작 나이로 짝지음). 소장 전이거나 결과 행이 없으면 랜딩과 같은 `POST /api/landing/chart`로 대운만 계산하고 줄거리는 블러로 잠근다.
- **입장 연출**: 필름이 오른쪽에서 들어오고 제목이 뒤따른다(transform·opacity만). 세션 저장소로 세션당 한 번만 재생하고, 서버 렌더와 어긋나지 않게 layout effect에서 정한다.
- **첫 화면 높이**: 375×812에서 관람권 아래 끝이 793px(헤더 포함)로 첫 화면 안에 들어온다(소장자·프로필 2개 기준 실측).
- **GA4**: `home_view`(state), `home_cta_click`(position: hero/ticket/daily/timetable), `home_profile_change`(profile_count, 이름·id 미전송).

## 7. 디자인 확정: E안 (2026-11-04)

v3 첫 구현은 "컨셉은 좋은데 UI 퀄리티가 낮다"는 피드백을 받아, 코드 전에 정적 시안으로 다시 설계했다.

1. **기준 실측**: 랜딩 375px에서 장면 여백 88~96px, 장면 제목 28~40px, 본문 15~16px/1.6, 주 버튼 56px, 오브젝트 343px, 한 화면에 오브젝트 하나.
2. **시안 3안**(A 필름 클로즈업, B 타이틀 카드, C 명반 상영관) → `designer` 에이전트 독립 비판 → **D안**(A 기본 + B 큰 제목 + C 실제 데이터).
3. 사용자 피드백("상단 섹션 퀄리티")으로 히어로만 고도화한 **E안** 확정.

**E안 히어로**

- 필름 칸 = 시드 기반 밤하늘(`libs/landing/night-sky.ts`): 대운궁 색 성운, 은하수 띠, 잔별 170, 중간 별 6, 주성 빛 번짐·십자 광채·이름, 비네트·그레인·빛샘. 이미지 파일 없이 SVG, 같은 명반이면 같은 하늘.
- 줄거리는 화면 안 자막(소장자만, 아니면 블러). 타임코드·"지금 상영 중"은 화면 안 작은 표시. 노란 테두리·알약 배지는 쓰지 않는다.
- 10년 썸네일 줄로 장면 이동(필름을 손으로 넘겨도 동기화). 아래 한 줄로 궁·별 설명(한국어 조사 자동).
- 영사기 켜짐 연출은 세션당 한 번, 주성은 은은하게 반짝인다. 모션 줄이기 설정에서는 모두 멈춘다.

**D안 아래 영역**

- 다음 상영작: "100명 중 98명"(인생→올해 760/774) + 관람권 2줄(올해 결과 화면의 실제 섹션 이름) + 외곽선 버튼(주 버튼은 히어로 하나).
- 오늘의 운세: 결과 문장은 보여 주지 않는다(산통을 직접 뽑는 경험 보호, `specs/daily-fortune.md`).
- 상영 시간표: 위에서 권한 운세는 빼고 본 운세는 맨 아래, 모든 행에 화살표.

**공용화**: 시드 난수는 `libs/landing/seeded-random.ts`로 옮겨 랜딩 `film-still.ts`와 함께 쓴다. 밤하늘 생성기는 랜딩 인생 필름 장면에도 쓸 수 있다(후속).

## 8. 관람권 찢기 + 상영관 입장 전환 (2026-11-04)

요청: 관람권으로 운세를 볼 때 찢기는 연출, 운세를 보러 갈 때 "상영하러 간다"는 전환. `designer`·`growth-strategist` 검토를 합쳐 확정했다.

**관람권 찢기** (`components/home/NextTicket`)

- **현재(2026-11-04 최종)**: 랜딩 관람권 장면(`TicketScene`)과 같은 움직임 — 꼬리표가 절취선 오른쪽 끝을 축으로 26px 내려앉으며 3° 기운다. 600ms(`TEAR_MS`, CSS `--tear-ms`) 뒤 상영관 입장으로 이어지고, 꼬리표는 떨어지거나 사라지지 않는다. 누를 때마다 나온다.
- 이전안(폐기): 1초 동안 불규칙 찢김선·종이 섬유 띠·160px 낙하·페이드 → "과하다"는 피드백으로 랜딩과 맞췄다. 기다리는 동안 목적지를 prefetch하고 3D 상영관을 받는 것은 그대로. 모션 줄이기는 찢김 없이 바로 넘긴다.
- 찢김선은 고정 시드 불규칙 다각형(피치 6~10px, 진폭 2~4px)이고 본체에 맞물리는 조각이 남는다. 찢긴 자리에 종이 섬유 띠. 규칙 톱니는 가위 자국처럼 보여 쓰지 않는다(designer).
- 안드로이드는 12ms 진동.

**상영관 입장** (`components/screening`, 루트 레이아웃에 있어 페이지가 바뀌어도 유지)

- 2026-11-04 재설계 1차: "순식간에 지나가고 네모 박스만 뜬다" → designer와 관객 시점 극장(좌석·커튼·카운트다운).
- 2026-11-04 재설계 2차: "조명이 뒤에 있어 이상하다", "이 전환은 로딩을 대체한다. 3,2,1 뒤에도 로딩이 더 걸릴 수 있다", "커튼이 너무 짜친다" →
  - **단계 기반**(`screening-policy.ts`): entering → waiting(무기한) → countdown → revealing. 고정 타임라인을 버렸다.
  - **준비 신호**: 목적지 경로 도착 + 공용 `<Loading/>`(`useScreeningHold`)이 모두 사라진 상태가 150ms 유지. 결과 페이지마다 따로 신호를 넣지 않아도 된다. 한 번 준비되면 되돌리지 않는다(래치).
  - **카운트다운은 준비된 뒤에만**: "1" 다음에는 반드시 본편이 나온다. 입장 연출 중에 이미 준비됐으면 2·1, 기다림이 있었으면 3·2·1(designer).
  - **긴 로딩**: 대기 중 스크린 안내가 2.8초마다 바뀌고(필름을 영사기에 거는 중 → 명반을 펼치는 중 → 곧 상영) 10초가 넘으면 "조금만 더 기다려 주세요". 20초가 지나면 걷고 페이지 자체 로딩 화면에 넘긴다(`max_wait`). 경로가 8초 안에 안 바뀌면 원래 화면으로 돌려준다(`timeout`). 건너뛰면 준비를 기다리지 않는다.
