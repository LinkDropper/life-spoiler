# 오늘의 운세 (Daily Fortune)

> 한 줄 요약: 로그인 사용자의 기존 프로필(생년월일시)과 오늘 날짜(일진)를 자미두수 명반에 매핑해, AI 호출 없이 사전 정의된 문구·값의 조합으로 "매일 달라지는" 무료 운세를 서버 컴포넌트에서 계산해 보여주는 재방문용 기능.

**상태**: **확정 (2026-10-14)**. 대표 결정·엔진 규칙(CTO/ziwei-expert) 반영 완료, 대표 미결 없음. 잔여는 "오픈 이슈"의 실행 확인 항목.
**작성일**: 2026-10-13 (개정 동일)
**구현 담당**: CTO → fullstack(페이지/UI/계측), ziwei-expert(엔진·캘리브레이션·문구 검수), designer(화면/공유 카드)

## 개요

### 배경

유료 상품(인생운세, 올해운세, 내년운세, 궁합)은 1회성 구매 구조라 재방문 이유가 약하다. "오늘의 운세"는 매일 다시 열 이유가 있는 습관형 콘텐츠이며, LLM 비용이 없어 변동비가 사실상 0이다. 1차는 로그인 사용자의 기존 프로필을 재사용해 재방문 습관을 만들고, 결과 화면에서 맥락이 맞는 유료 상품으로 연결한다.

### 목표

1. **리텐션**: 가입자가 하루 1탭(프로필 1개면 선택 생략)으로 오늘 결과를 본다.
2. **전환**: 결과 화면의 인생운세 CTA(구매자는 올해운세/궁합)로 유료 퍼널에 진입시킨다.
3. **바이럴**: 결과 공유 카드로 수신자를 로그인 유도 CTA로 연결한다.
4. **품질**: "어제와 비슷하다 / 친구와 똑같다 / 점수와 설명이 안 맞는다" 체감을 구조적으로 막는다.

### 기존 기능과의 경계

| 항목 | 유료 운세 | 친구 우주 | 오늘의 운세 |
|---|---|---|---|
| 로그인 | 필요 | 불필요 | **필요 (1차)** |
| 결과 산출 | Gemini 해석 | 결정론 매트릭스 | 결정론 매트릭스 + 일진 |
| 결과 변화 | 구매 시점 고정 | 등록 시점 고정 | **매일 변화 (KST 자정)** |
| 저장 | `fortunes` | `universes` 계열 | **없음 (서버 컴포넌트에서 재계산)** |
| `fortune_type` | 발급 | 미발급 | **미발급** (CHECK 제약 5개 테이블 마이그레이션 불필요) |

## KPI (로그인 사용자 기준)

목표치는 **가설**이며 출시 후 2주 베이스라인으로 보정한다 (출처 미확인 추정).

| 구분 | 지표 | 정의 | 목표 가설 |
|---|---|---|---|
| 활성 | 사용률 | 가입자(주간 활성) 중 오늘의 운세 `daily_view` 1회 이상 비율 | 출시 4주 후 15~25% |
| 리텐션 | D1 / D7 재방문 | `daily_view`의 사용자·날짜로 산출 (첫 조회 다음 날 / 7일 내 2회 이상) | D1 25~35%, D7 15~20% (로그인 사용자라 비로그인보다 높게 가정) |
| 전환 | 유료 CTA 클릭률 | 조회 대비 `daily_cta_click` | 3~5% |
| 전환 | 경유 결제 전환 | 30일 내 오늘의 운세 CTA 경유 첫 유료 결제 유저 / 조회 UV | 0.5~1% |
| 바이럴 | 공유율 / 수신자 전환 | 조회 대비 `daily_share_click` / `daily_shared_link_open` 대비 `daily_shared_cta_click` | 4~6% / 10~15% |
| 품질 | 시간 미상 비중 | `profile_time_known=false` 비율 | 모니터링 |

**북극성**: 주간 활성 조회자 중 "7일 내 3회 이상 조회" 비율.

### 계측 이벤트 (GA, 1차 필수)

`libs/analytics/google-analytics.ts`의 `trackEvent` 사용. **생년월일시 등 개인정보 파라미터 금지.**

| 이벤트 | 파라미터 |
|---|---|
| `daily_entry_click` | `source` (home 등) |
| `daily_profile_select` | - |
| `daily_view` | `profile_time_known`, `is_return_day` |
| `daily_category_expand` | `category` |
| `daily_cta_click` | `category`, `cta_product` |
| `daily_share_click` | `channel` |
| `daily_shared_link_open` | - |
| `daily_shared_cta_click` | - |
| `daily_time_unknown_notice_click` | - |

공통 파라미터: `date`(KST), `confidence`(time_known / time_unknown), `overall_level`, `category`, `cta_product`. `is_return_day`는 클라이언트 localStorage에 **마지막 열람 KST 날짜만** 저장해 판정한다 (개인정보 아님, DB 불필요).

## 사용자 시나리오

### 시나리오 1: 첫 조회 (프로필 보유)

```
1. 로그인 사용자가 홈의 "오늘의 운세" 카드(KO 로케일)를 탭한다.
2. 프로필이 여러 개면 /profiles?type=daily에서 선택한다. 1개뿐이면 선택 없이 바로 결과로 이동한다.
3. 서버가 프로필과 오늘(KST) 일진으로 결과를 계산해 렌더한다.
4. 사용자가 총운·카테고리·예고 키워드를 확인하고 공유하거나 CTA를 탭한다.
```

### 시나리오 2: 다음 날 재방문

```
1. 홈 카드를 탭한다 → 프로필 1개면 즉시 오늘 결과 (재입력 없음, 기존 프로필 재사용).
2. 어제와 다른 한 줄·키워드를 확인한다.
```

### 시나리오 3: 공유 카드 수신자

```
1. 수신자가 공유 링크를 연다 (결과 키 기반 카드: 오늘의 한 줄 + 키워드만).
2. "내 오늘도 보기" CTA를 탭하면 비로그인 시 로그인 후 **홈으로** 이동한다 (복귀 리다이렉트는 1차 미구현. 신규 가입자는 프로필 등록이 필요해 복귀만으로는 결과를 볼 수 없기 때문). 퍼널 `daily_shared_cta_click` → 로그인 → `daily_view`를 계측하고, Phase 2 비로그인 입력과 함께 해결한다.
```

### 시나리오 4: 태어난 시간을 모르는 프로필

```
1. 시간 미상 프로필로 진입하면 시간 독립 신호 중심으로 결과가 계산된다.
2. 등급은 2~4단계만 나오고, 결과 상단에 "시간과 상관없는 흐름 위주로 보여드려요" 중립 안내가 노출된다. 프로필 수정 화면이 없어 1차에는 유도 문구·링크를 넣지 않는다 (수정 화면이 생기면 Phase 2에서 추가).
```

## 결과 화면 구성 (모바일 375px)

```
┌───────────────────────────────────┐
│ 오늘의 운세            [프로필 변경]│
├───────────────────────────────────┤
│ 10월 13일 화요일 · 지민님의 오늘    │
│ ┌───────────────────────────────┐ │
│ │ 오늘의 한 줄                    │ │  ← 스포일러 컨셉 헤드라인 (공유 카드 중심)
│ └───────────────────────────────┘ │
│ [시간 미상일 때] 안내 배너          │
├───────────────────────────────────┤
│ 총운   ★★★★☆  환한 날             │
│ 본문 1~2문장                       │
├───────────────────────────────────┤
│ 애정 / 재물 / 일·학업 / 건강        │  ← 각 행: 아이콘·라벨·별·등급명, 탭하면 펼침
│ (daily_category_expand)            │
├───────────────────────────────────┤
│ 오늘의 예고 키워드                  │
│ 색 / 소품 / 숫자 / 시간대 + 이유 1줄│
├───────────────────────────────────┤
│ 오늘의 주의 포인트 · 오늘의 팁      │
├───────────────────────────────────┤
│ [유료 CTA 1개]  [공유하기]          │
│ 면책: 엔터테인먼트용 간이 규칙이에요│
│ (流日은 유파마다 해석이 달라요).    │
│ 자정(KST)에 바뀌어요. [자세히 ▾]    │
└───────────────────────────────────┘
```

- **카테고리**: 총운 + 애정(관계 포함) / 재물 / 일·학업 / 건강.
- **등급 표시**: 별 개수와 등급명 병기, 숫자 점수 없음. 별 아이콘 `aria-label="5점 만점에 4점, 환한 날"`. 최하 등급 "살펴 가는 날"도 사건 단정 없이 행동 제안형 문구만 쓴다.
- **"자세히" 접힘 영역**: 자시(23시) 경계 차이 한 줄 설명을 넣는다 (1차에 공개 FAQ 페이지가 없으므로 결과 하단에 배치).
- **키워드**: 색은 이름 텍스트 병기, 숫자는 한 자리 1개(복권 번호 연상 방지), 소비 유도 문구 금지. 전문 용어(오행 등) 표면 노출 금지, 이유 문구는 일반어로.
- **주의 포인트**: 건강은 level 1일 때만 후보, 그 외엔 나머지 카테고리 중 최저 (규칙 7-1). 사건 단정 금지.
- **건강** (포함 확정): 컨디션·생활 습관 수준으로 제한, 질병·치료·약 등 의료 어휘 금지, 건강 카테고리에는 유료 CTA 없음.

## 결과 생성 규칙 (확정: CTO / ziwei-expert)

> 이전 초안에서 기각된 규칙: 일지 직대응 流日(같은 날 전원이 같은 위치), 일지 12일 주기를 전제한 문장 회전 근거(및 36일/720일 주기 수치; 회전 자체는 규칙 7에서 순수 회전 장치로 재정의), 본명 고정 12궁→5카테고리 분할, 시간 미상 시 전면 축 전환+별도 F 슬롯(대안으로만 보존), 양력 연도 기반 일운. 아래가 최종 규칙이며 사화 최종 산식은 ziwei-expert 확정.

### 입력과 순수성

- 입력: 프로필(생년월일시·성별·이름은 `profiles`에 이미 존재 → 필수 스키마 이슈 해소), 오늘 날짜(KST).
- 순수 함수 `calculateDailyFortune(chart, kstDate)`. 내부에서 `Date.now()`·`Math.random()` 호출 금지.
- 출력 DTO에 명반 구조·생년월일시를 담지 않는다.

### 규칙

| # | 규칙 |
|---|---|
| 1 | **일진**: 기존 의존성 `korean-lunar-calendar`의 `getChineseGapja()` 사용 (신규 구현 불필요, 2026-10-13=庚申日 확인). 일운은 라이브러리 간지(음력 설 경계)를 그대로 쓰며, `yearly.ts`의 `getYearStemBranch`는 양력 연도 기준이라 일운에 쓰지 않는다 (1/1~설날 구간 오류). 날짜는 **KST 자정 기준** (서버 UTC → KST 변환 필수). 자시(23시) 차이는 결과 하단 안내 한 줄 |
| 2 | **流日 명궁** = 流月 명궁 + (음력일 − 1) 순행 (두수 전통). 流月은 `yearly.ts` 월건 간이법(정월=寅), 음력월 기준, 윤달은 본월과 동일 |
| 3 | **일간 사화** = 하루 변동의 주동력 (가중 1.0). 배경 가중: 대운 0.3, 유년 0.5, 유월 0.6 |
| 4 | **카테고리**: 流日 명궁 기준 상대 궁(역할 궁) + 그 궁의 삼방사정 평가. 총운=명궁, 애정=부처(-2), 재물=재백(-4), 일·학업=관록(-8), 건강=질액(-5). **사화 판정**: "사화 별이 앉은 본명 궁이 해당 카테고리의 流日 역할 궁 삼방사정 안에 있는가"로 판정한다 (밝기와 사화가 같은 궁 축을 보므로 규칙 6 충족). 최종 산식은 ziwei-expert 확정 |
| 5 | **등급 5단계**, 분위 컷으로 분포 **10/25/30/25/10%** 고정. 개인 편향 ±6 클램프. 같은 극단 등급(1 또는 5)이 3일 연속이면 사흘째는 한 단계 중앙 쪽으로 이동 |
| 6 | **점수-텍스트 일치**: 별 개수·등급명·카테고리 문구는 모두 같은 `level`에서 파생. 점수 로직과 문구 로직을 분리하지 않는다 |
| 7 | **문장 변형** (같은 키 안의 동의어 선택, `Math.random` 금지): 한 줄(hl)·총운(ob)은 **순환**, 카테고리 본문(cb)은 **시간 확정 사용자만 순환**(시간 미상 사용자는 해시 - 순환으로 하면 시간 미상 중앙값이 12일에서 6일로 줄어 반복이 심해짐) — `variantIdx = (personOffset + floor(dayNumber / 12)) mod V`. 이는 일지 주기를 전제하지 않는 **순수 회전 장치**다 (이전 "12일 라운드로빈" 서술 및 36일/720일 수치는 폐기 유지). 나머지 슬롯(변수·주의·팁·키워드)은 `hash(personSeed, kstDate) mod V` |
| 7-1 | **주의 포인트 선정**: 건강은 **level 1(살펴 가는 날)일 때만** 후보. 그 외에는 나머지 카테고리 중 최저. 근거: 건강이 주의 포인트인 날이 31.6%(제한 없음) → 25.2%("2 이하", 중간 단계) → **7.3%(확정, 최종 시뮬레이션)**로 내려간다 (불안 유발 방지). 건강 L1 주의 문구 9개는 생활 습관 제안형으로 수정 완료, 증상·단정·불안 표현 금지 테스트 추가 |
| 8 | **시간 미상(기본안)**: 점수는 12시진 명반의 points를 각각 계산해 평균 후 **0.6배 수축** (연속값이라 평균이 성립 - 이산값인 owner 한줄평과 다른 경우). **등급**: 시간 미상 모집단 별도 분위 컷 + 극단 등급 안쪽 접기 → **2·3·4등급만 (약 32/31/37%), 1·5등급 없음**. 원칙: "시간을 모르면 극단 판정을 하지 않는다". 테마는 시간 독립 신호(일간 사화의 별, 일진 오행)로 **시간 확정과 같은 S 슬롯을 재사용** (F 네임스페이스 없음). 키워드는 오행국 대신 **생년 납음 오행**, 시간대는 일진 지지. 대안(축 전환 + F 슬롯)은 ziwei-expert가 슬롯 확정 시 결정 |
| 8-1 | **연 경계**: 일운은 라이브러리 간지(음력 설 경계), 기존 `yearly.ts`는 양력 연도 기준. `yearly.ts` 수정은 별도 이슈로 확정(확정 결정 17). 그 전까지 연초 1~2개월 두 상품의 유년 기준 불일치를 수용한다 |
| 9 | **키워드**: 보완 오행(본명 오행국 vs 오늘 일간 오행의 상생상극)으로 색·숫자·소품. 숫자는 생수/성수 중 날짜 해시로 선택. 소품은 오행별 약 8개 풀. 시간대(Phase 2 방향 포함)는 일간 화록이 앉은 궁의 지지. 내부 명칭은 "용신"이 아니라 "보완 오행" |

## 공유

- 링크 `/daily/share?t=…` + OG 카드(`next/og`). **HMAC 서명은 CTO가 철회**했고 엄격한 화이트리스트 검증으로 간다.
- **토큰 요구사항**: 토큰은 키만 담는다 (날짜, headline 슬러그, level들, 키워드 슬러그). 생년월일시·이름·프로필 ID 금지.
- **서버 검증**: 모든 슬러그가 사전에 존재해야 함 / level은 1~5 enum / 날짜는 YYYY-MM-DD이며 범위는 서비스 시작일~오늘(KST) / 하나라도 실패하면 `INVALID_SHARE_TOKEN` → `/daily` 이동.
- **출력 원칙**: 쿼리 값을 그대로 화면에 출력하는 경로 0개 (사전 조회 결과만 렌더). 사전 슬러그는 append-only라 과거 링크가 유지된다. 토큰이 불변이라 CDN 캐시 가능.
- 공유 페이지는 noindex이며 robots.txt로는 막지 않는다 (링크 미리보기 봇이 OG를 읽어야 함).
- 수신자 화면: 오늘의 한 줄 + 키워드 + "내 오늘도 보기" (비로그인 시 로그인 후 홈으로 이동, 복귀 리다이렉트 1차 미구현. 시나리오 3 참조).
- 이미지 저장: 기존 공유 드로어 재사용 가능 시 앞당김 (CTO 확인).
- **공유 링크에는 기존 방식대로 `ref`(사용자 id)가 붙는다.** `profileId`·생년월일시·이름은 포함하지 않는다. 보상 구조는 growth 후속이며, 보상 연계 시 서명 재검토는 오픈 이슈.

## 유료 CTA 연결 (확정: 인생운세 단일화)

- 결과 화면의 유료 CTA는 **인생운세 1개로 단일화**한다. 카테고리별 상품 매핑은 두지 않는다 (기각 사유: 올해운세·궁합이 인생운세 구매 시 무료인 판매 구조와 충돌 가능).
- **인생운세 구매자**에게는 인생운세 CTA 대신 **올해운세/궁합 보기**로 대체 노출한다 (구매 상태 판정은 기존 `hasPaidFortune` 계열 재사용, CTO 확인).
- **건강 카테고리 화면에는 유료 CTA를 붙이지 않는다** (의료 오해·불안 마케팅 방지). 건강이 주의 포인트여도 CTA는 결과 화면 공통 위치의 인생운세 CTA만 노출한다.
- CTA 문구에 전문 용어 금지. 올해운세 연결 시 연도 분기는 `libs/fortune/yearly-editions.ts`(`resolveTargetYear`)를 사용하고 `"yearly_2027"`을 하드코딩하지 않는다.

## SEO / noindex / 데이터

- 결과 `/fortune/daily/[profileId]`·공유 `/daily/share`: `NOINDEX_METADATA` (`libs/seo/metadata.ts`). `app/robots.ts` 원칙과 동일하게 robots.txt로 막지 않는다.
- `/daily`: KO 전용 색인 소개 랜딩 (계산 방식 설명, 고정 예시 결과, FAQ 서버 HTML, 로그인 유도 CTA). `app/sitemap.ts` `PUBLIC_PAGES`에 **로케일 제한 필드**를 추가해 ko만 hreflang·등재한다. 자시(23시) 차이 설명도 FAQ에 포함.
- DB 저장·마이그레이션·신규 `fortune_type` 없음. 결과는 재계산 가능한 순수 함수. 열람 로그는 만들지 않고 GA 이벤트로 대체.
- 문구 사전은 슬러그 + 코드 고정 (append-only 슬러그 계약, 친구 우주 `libs/universe/one-liner.ts` 선례).
