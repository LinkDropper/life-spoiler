## 2. 콘텐츠로서 재미있는가? — 🟢 YES, Gemini보다 확실히 재미있음

### 2.1 관찰 디테일의 승리

GPT가 **실제 사진을 본 흔적**이 문장 곳곳에 드러남:

```
"헤어라인이 둥글게 감싸여" (1번 이마)
"눈썹의 짧은 선과 함께 보면" (1번 눈)
"콧대가 곧게 내려오다가 코끝에서 크게 퍼지지 않아요" (1번 코)
"미간은 넓게 열리고 눈매는 가늘게 눌려 있어" (3번 히어로)
"눈두덩은 깊지 않아요" (3번 눈)
```

Gemini가 hint 문구를 재포장하던 반복 패턴(`이마가 시원하게 드러나고...`)과 달리, GPT는 **랜드마크 기반 관찰을 관상 해석과 자연스럽게 엮음**. reference/overall.md 톤과 가까워짐.

### 2.2 비유와 언어 감각

- 2번 [종합 한 줄]: **"고해상도 화면처럼 또렷한 눈과 코어 밸런스형 상"**
- 3번 [종합 한 줄]: **"로딩은 느려도 결과값은 또렷한 앱업데이트형 상"**

→ `ONE_LINE_DEFINITION_LANES`의 "현대 비유형" 레인이 의도대로 작동. Gemini는 이 레인을 프롬프트에서 받고도 "단정한 추진력" 같은 무난한 결과로 떨어뜨렸음. GPT는 지시 준수율이 확실히 더 좋음.

### 2.3 바이럴 훅 감각

- 2번 자주 받는 오해: **"'말이 적어서 다가가기 어렵다'는 오해, 실제로는 반응이 빠른 쪽이에요"**
- 3번 자주 듣는 말: **"'말수는 적은데 눈치가 빠르다'는 말, 들어보셨죠?"**

Gemini 버전보다 **대조·반전** 구조가 또렷하고 짧아 SNS 캡처용으로 더 적합.

### 2.4 축 다양화

highlights에 "위트·재치·여백·속도·유머·관심 확장" 같은 어휘가 자연스럽게 섞임. Phase 17.5의 지성 축 상한 validator가 의도한 결과에 GPT가 더 쉽게 도달.

### 2.5 부위별 점수 편차 ← 새로운 발견

**한 인물 내부 점수 편차가 크게 확장됨** (2번 인물):
- 눈 **9.7**, 입 **9.5**, 광대 **9.7**, 전체 균형감 7.0, 턱 7.0, 코 7.0
- 편차 2.7점 — Gemini는 부위별 편차가 평탄했는데 GPT는 **부위별 기여도 차이를 실제로 반영**.

Phase 17.3의 비선형 매핑이 GPT에서 더 뚜렷이 작동. 단, 아이러니하게 **총점 편차는 여전히 좁음**(평균의 법칙).

## 3. 문제 — 5개 이슈

### 3.1 🔴 히어로 영역 첫 문단 중복 3/3 — 신규 버그

```
(1번)
라인 3: "이마의 넓은 여백과 곧게 시작되는 코선이 먼저 눈에 들어오고..."
라인 6: "이마의 넓은 여백과 곧게 시작되는 코선이 먼저 눈에 들어오고..." ← 완전 동일 복붙
```

3명 모두 **히어로 첫 문단이 subDefinition/summary 이전과 동일**. 렌더링 레이아웃 버그 또는 스키마 구조 해석 오류.

**원인 추정**:
- OpenAI strict schema는 필드 누락 허용 안 함. GPT가 `subDefinition`과 `overallScore.summary` 또는 히어로 영역 필드 하나를 같은 내용으로 채웠을 가능성.
- 또는 UI 렌더에서 동일 필드를 두 번 호출.
- 실제 DB 저장된 JSON을 확인해 코드 버그인지 LLM 응답 중복인지 확인 필요.

### 3.2 🔴 분야별(연애/재물/직장) 섹션 3명 동질화

```
(1번 연애)  "은근신호 타입" / 표현 아끼지만 신호는 또렷한
(2번 연애)  "은근배려 타입" / 담백한 표정 속에 챙김이
(3번 연애)  "은근히 스며드는 타입" / 표현은 아끼지만 시선과 챙김이
```

"은근"이 3번 모두 등장 + "표현은 아끼지만" 2번 모두 같은 문장 구조. 
Phase 18 부위 조합 강제는 [종합인상]에만 걸려 있고 분야별 섹션은 미적용. **분야별에도 부위 조합 강제 주입 필요**.

재물운 3명 모두 "충동보다 한 번 더 살피는 / 한 번 더 따져보는 계산형" 같은 보수형 소비 묘사. 
실행 소비형·감정 소비형 같은 다른 축으로 분화 안 됨.

### 3.3 🟡 "부드럽/단정/은근" 새 수렴 어휘

Gemini에서 막았던 "안정/꾸준"은 확실히 감소. 그러나 GPT가 **"부드럽/단정/은근/조용/차분"** 세트로 도피:

| 어휘 | 1번 | 2번 | 3번 | 합계 |
|---|---|---|---|---|
| 부드럽 | 3 | 3 | 3 | **9** |
| 단정 | 3 | 1 | 2 | **6** |
| 은근 | 1 | 3 | 1 | **5** |
| 차분 | 0 | 2 | 1 | 3 |

블랙리스트 확장 필요: "부드럽" 상한을 4→3, "단정" 3, "은근" 3 추가.

### 3.4 🟡 [전체 균형감] 점수 3/3 모두 7.0

```
1번 전체 균형감: 7.0
2번 전체 균형감: 7.0
3번 전체 균형감: 7.0
```

균형감 점수가 완벽히 수렴. Gemini는 8.5~8.9 수렴이었고 이게 Phase 17 balance weight를 0.15로 낮춘 이유였는데, GPT에서는 **7.0 한 점에 고착**. 
Phase 17.4 재설계된 9분기가 제대로 분기는 타고 있는데(1번 하부 우세, 2번 둥근형, 3번 세로형) `fit` 계산이 비슷하게 떨어지는 듯.

balance scorer 점수 계산식(`7.0 + expanded * 2.7`) 자체에 문제는 없고, 세 명의 `faceRatio`, `samjeong`이 fit 0.4 근처로 수렴한 결과로 보임. **balance의 fit 계산 width를 더 축소**하거나 **balance에만 다른 매핑 공식** 적용 검토.

### 3.5 🟡 내부 용어 노출 1회

3번 [종합 인상]: **"→ 먼저 보고, 그다음 움직이는 흐름이 느껴져요"**

화살표(`→`)는 프롬프트 예시에서 썼던 내부 표기. 사용자 노출 시 어색. 프롬프트에서 → 사용 금지를 명시하거나 post-processing 필요.

## 4. GPT vs Gemini 종합 평가

### GPT가 더 나은 영역
1. **관찰 디테일** — 이미지 기반 구체 묘사 (헤어라인, 눈두덩, 미간)
2. **비유 창의성** — "고해상도 화면", "앱업데이트형" 같은 현대 레인 제대로 구현
3. **축 다양화** — 위트·재치·여백·속도를 자연스럽게 섞음
4. **바이럴 훅** — 오해/자주 듣는 말 문장 임팩트 강함
5. **부위별 점수 편차** — 한 인물 내 7.0~9.7까지 과감하게 벌어짐
6. **첫 문장 분화** — 3/3 서로 다른 부위 조합으로 진입

### Gemini가 더 나은 영역
1. **레이아웃 안정성** — GPT의 히어로 중복 버그 없음
2. **비용·지연** — Gemini Flash가 토큰 단가 낮음 (실측 필요)

### 구조적 공통 한계
1. **총점 편차 1.0** — 두 모델 동일. 측정값 기반 구조의 한계
2. **분야별 섹션 동질화** — Phase 18 조합 강제가 [종합인상]만 커버
3. **전체 균형감 점수 수렴** — balance scorer 매핑 문제 (Gemini 8.x 수렴, GPT 7.0 수렴 — 어느 쪽이든 편차 0)

## 5. 추가 제안

### 🥇 Phase 20.1 — 히어로 중복 버그 조사 (30분, 우선)
- DB에 저장된 실제 JSON 응답 확인 → 필드 중복이 LLM인지 UI 렌더인지 판별
- LLM 응답 문제라면 OpenAI strict schema에 `minLength`/`maxLength` 추가 또는 프롬프트에 "서로 다른 필드" 강조
- UI 렌더 버그라면 `app/face-spoiler/r/[shareId]/page.tsx` 렌더러 점검

### 🥈 Phase 20.2 — "부드럽/단정/은근" 블랙리스트 추가 (10분)
```typescript
{ word: "부드럽", max: 3 },  // 4→3 강화
{ word: "단정", max: 3 },    // 신규
{ word: "은근", max: 3 },    // 신규
```

### 🥉 Phase 20.3 — 분야별 섹션에도 부위 조합 강제 (45분)
Phase 18의 `buildRegionCombinationBlock`을 Stage C(interestAreas)에도 적용:
- 연애운: 입·눈썹·눈 중 점수 상위 2
- 재물운: 코·입·턱 중 점수 상위 2
- 직장운: 이마·코·턱 중 점수 상위 2
→ 분야별 섹션이 매 인물마다 다른 부위 조합으로 진입

### Phase 20.4 — balance scorer fit 계산 다변화 (30분)
현재 `balanceFit = clamp(1 - samjeongVariance * 5, 0, 1)` + `faceBalanceFit`만으로 fit이 0.4 근처 수렴.
- `faceRatio` 추가 반영 (세로/둥근 극단에 더 민감)
- `upperLowerDiff` 크기도 fit에 반영 → 뚜렷한 편향이 있는 얼굴은 fit이 더 높거나 낮음
- 목표: balance 점수도 최소 7.2~9.0 편차 달성

### Phase 20.5 — "→" 등 내부 표기 제거 프롬프트 보강 (5분)
FORBIDDEN_RULES에 "화살표(→, ⇒), 원형 불렛(·), 마크다운(**, ##) 등 특수 문자 사용 금지" 추가.

## 6. 결론

**8.2 / 10** — GPT-5.4 mini가 **콘텐츠 재미도에서 Gemini를 분명히 앞섬**. 관찰 디테일, 비유 창의성, 축 다양화, 바이럴 훅 품질 모두 윗단. **990원 유료 리포트의 "값어치" 체감이 명확히 개선됨**.

단, 다음 셋은 GPT로 교체했다고 자동 해결되는 게 아니라 **구조적/튜닝 과제**로 남음:
- 총점 편차 좁음 (측정값·평균의 법칙 문제)
- 분야별 섹션 동질화 (Phase 18 적용 범위 확장 필요)
- 전체 균형감 점수 수렴 (balance scorer 튜닝)
- 히어로 중복 버그 (코드/LLM 판별 필요)

**추천 다음 단계**:
1. **[필수]** Phase 20.1 히어로 중복 버그 조사 — 이건 사용자 경험 직접 타격
2. **[큰 효과]** Phase 20.3 분야별 섹션 부위 조합 강제 — 분야 동질화 가장 큰 해소
3. **[간단]** Phase 20.2 블랙리스트 확장 + Phase 20.5 → 제거 — 10~15분 작업

Phase 20.1 + 20.2 + 20.5 먼저 (45분 내), 이후 20.3/20.4로 확장 추천.
