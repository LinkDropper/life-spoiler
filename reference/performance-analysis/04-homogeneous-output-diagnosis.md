**작성**: 2026-04-21
**문제**: 5명의 완전히 다른 인물 사진에 대해 [종합인상]·[전체 균형감] 결과가 거의 동일한 문장·어휘·구조로 수렴

## 🔬 원인 분석 (우선순위 순)

### 1️⃣ 주원인 — Region hint가 **3구간 템플릿**이라 대부분 사진이 "가운데 구간"에 몰림

`libs/face-spoiler/region-scorer.ts` 의 hint 생성 로직:

```typescript
// scoreForehead (예시)
if (m.foreheadWidthRatio > 0.95) {
  hint = "이마가 넓은 편이라 시야와 통찰의 기운이 또렷한 쪽";
} else if (m.foreheadWidthRatio < 0.82) {
  hint = "이마가 좁은 편이라 집중과 장인 기질이 담기는 쪽";
} else {
  hint = "이마 비율이 안정적으로 잡혀 있어 생각의 정리력이 또렷한 쪽";  // ← 대부분 여기!
}
```

**한국인 평균 이마 비율 분포: 0.82~0.95 구간에 약 80%가 들어옴** → 대부분 사진이 같은 hint를 받음.

다른 부위도 동일한 문제:

| 부위 | 중간 구간 hint (가장 많이 선택됨) | 한국인 평균 분포 |
|---|---|---|
| forehead | "이마 비율이 안정적으로 잡혀 있어 생각의 정리력이 또렷한 쪽" | 0.82~0.95 |
| eye | "눈매가 안정적으로 정돈되어 상대를 보고 판단하는 쪽" | eyeCornerAngle 1~7° |
| nose | "코가 얼굴 중심에 안정적으로 자리 잡아 현실 감각이 또렷한 쪽" | 0.24~0.32 |
| mouth | "입매가 차분하고 정돈된 편이라 말의 무게감이 있는 쪽" | 0.34~0.46 |
| chin | "턱선이 안정적으로 잡혀 있어 버티는 힘이 읽히는 쪽" | 0.3~0.6 |
| **balance** | **"한 군데가 튀기보다 전체가 조화롭게 잡혀 있어 안정감이 묵직한 쪽"** (고정) | — |

→ `scoreBalance`는 **아예 hint가 하나 고정**("한 군데가 튀기보다...")이라 **모든 사진이 같은 문구**를 받음!!

**결과적으로**:
- 5명의 서로 다른 얼굴에 LLM에 들어가는 **hint 텍스트 블록이 거의 동일**
- LLM은 이미지보다 hint 문구를 우선 참조하는 경향 → **hint 어휘를 그대로 복붙** → "안정적인", "또렷한", "묵직한"이 반복

### 2️⃣ 부원인 — 시스템 프롬프트의 "hint 방향성 준수" 지시

`prompts/text-report.v3.ts:261-271`:
```markdown
## 📊 부위별 관찰 hint (코드 결정적 산출물)

각 부위의 인상 기여 방향이 아래와 같이 코드로 판정되어 있어요.
LLM은 이 hint를 해석의 **출발점**으로 사용하고, 구체적 문장은 창작하세요.

규칙:
- hint의 방향성을 거스르지 말 것
- hint의 단어를 **그대로 복사하지 말 것**
```

→ "거스르지 말라" 는 강한 제약 + "단어 복사 금지" 는 약한 제약. 실제로는 **단어 복사 경향**이 강함 (LLM이 안전한 선택).

### 3️⃣ 보조 원인 — Balance scorer의 hint가 고정값

```typescript
const scoreBalance = (m: FaceMetrics) => {
  // ...
  const hint = "한 군데가 튀기보다 전체가 조화롭게 잡혀 있어 안정감이 묵직한 쪽";
  //            ↑ 항상 같은 문장. 사진·metrics에 따른 분기 없음!
};
```

**이게 [전체 균형감] 섹션이 거의 복붙되는 직접 원인**. 모든 사진이 `scoreBalance`에서 완전히 동일한 hint 받음.

### 4️⃣ 간접 원인 — 모델의 한국어 창작 보수성

Gemini 2.5 Flash는:
- 한국어로 "안전한" 표현에 수렴하는 경향
- hint 복붙 지시를 약하게 지켜도 문제 없다고 판단
- 사진별 차이보다 "일관된 톤" 유지에 우선순위

→ 모델 한계도 있지만, 프롬프트가 하드 유도하지 않아 허용됨.

### 5️⃣ 부차 원인 — 이미지 관찰 우선순위 낮음

현재 프롬프트 구조:
1. FORBIDDEN_RULES (금지)
2. TONE_V3_RULES (톤)
3. **동물상 컨텍스트 블록** ← 강한 주입
4. **부위 hint 블록** ← 강한 주입
5. Stage별 지시

**이미지 관찰 지시는 "섹션별 본문 작성 가이드"에만 암시적으로 등장**. LLM이 이미지를 보지 않고 텍스트 블록만 재조합해도 그럴듯한 결과가 나와버림.

## 📊 "모델 한계 vs 프롬프트 문제" 진단

| 원인 | 영향도 | 수정 난이도 |
|---|---|---|
| Region hint가 3구간 템플릿 | 🔴 매우 큼 | 🟢 쉬움 |
| Balance hint가 고정 문자열 | 🔴 매우 큼 | 🟢 매우 쉬움 |

→ **프롬프트·hint 설계가 원인의 70~80%**, 모델 한계는 20~30%.

## 🛠 해결 방향 (6가지)

### 옵션 A ⭐ **Balance hint 다양화** (최우선, 30분)

`scoreBalance` 의 고정 hint를 **여러 조건 분기**로 변경:

```typescript
const scoreBalance = (m: FaceMetrics) => {
  const samjeongUpper = m.samjeong.upper;
  const samjeongLower = m.samjeong.lower;
  const faceRatio = m.faceRatio;

  let hint: string;
  if (samjeongUpper > 0.36) {
    hint = "상부(이마·눈)가 넓어 사고와 통찰의 무게가 앞서는 균형";
  } else if (samjeongLower > 0.38) {
    hint = "하부(턱)가 넉넉해 행동·실행이 묵직하게 받쳐주는 균형";
  } else if (faceRatio > 1.25) {
    hint = "세로로 긴 얼굴선이 내면의 깊이를 담아내는 균형";
  } else if (faceRatio < 0.98) {
    hint = "둥근 얼굴선이 포용과 친화의 온기를 머금은 균형";
  } else if (Math.abs(samjeongUpper - samjeongLower) < 0.03) {
    hint = "삼정이 고르게 맞춰져 어느 면도 편향되지 않은 균형";
  } else {
    hint = "한 군데가 튀지 않으면서도 각 부위가 자기 자리를 지키는 균형";
  }
};
```

→ **Balance hint가 사진별로 6종 중 하나**로 선택됨. [전체 균형감] 섹션의 복붙 현상 즉시 해소.

### 옵션 B ⭐ **Region hint 세분화 3구간 → 5~7구간** (우선, 1시간)

각 부위의 분기 조건을 세분화. 예를 들어 `scoreForehead`:

```typescript
if (m.foreheadWidthRatio > 1.0) {
  hint = "이마가 광대보다도 넓어 시야·통찰이 앞서는 상부형";
} else if (m.foreheadWidthRatio > 0.95) {
  hint = "이마가 넓직해 기획과 구조화의 기운이 또렷";
} else if (m.foreheadWidthRatio > 0.88) {
  hint = "이마 폭이 평균보다 살짝 넓어 균형감 위주의 판단";
} else if (m.foreheadWidthRatio > 0.82) {
  hint = "이마 비율이 중간대에 안정적으로 자리 — 사고가 정돈된 쪽";
} else if (m.foreheadWidthRatio > 0.75) {
  hint = "이마가 좁은 편이라 한 곳에 몰입하는 집중형";
} else {
  hint = "이마가 좁고 기운이 응축된 장인 기질 쪽";
}
```

→ 중간 구간을 3개로 쪼개면 평균 주변의 사진들이 **서로 다른 hint** 받음.

### 옵션 C ⭐ **이미지 관찰 우선 지시 강화** (30분)

시스템 프롬프트 상단에 명시적 지시 추가:

```markdown
## 🖼 이미지 관찰 지시 (최우선)

이 리포트는 **첨부된 사진을 직접 관찰하여 작성**해야 합니다.

1. **먼저 이미지를 본 후**, 당신의 눈으로 관찰한 구체적 특징 3~5개를 마음속으로 정리하세요
   (예: 눈썹 결의 방향, 콧대 각도, 입꼬리 기울기, 턱 선의 곡률)
2. **그다음** 아래 제공되는 hint를 참고해 방향성을 조정하세요
3. hint를 복붙하지 말고, 이미지에서 직접 관찰한 표현을 최우선으로 사용하세요

❌ 금지 패턴: "안정적으로 잡혀 있어", "묵직한 안정감", "한 군데가 튀기보다 조화롭게" 같은 hint 어휘 그대로 쓰기
✅ 권장: 이미지에서 본 그대로 — "눈썹 안쪽이 살짝 올라가 있어", "콧대 중간이 곧게 떨어져"
```

→ LLM이 hint 복붙에서 벗어나 **이미지 기반 서술**에 더 집중.

### 옵션 D — **측정 수치를 의역해 프롬프트에 주입** (1시간)

현재: hint 텍스트만 (의미적)
개선: 수치를 의역한 상대 비교 추가

```typescript
const buildRegionScoresBlock = (regionScores, faceMetrics) => {
  return `
## 📊 부위별 관찰 hint + 상대 비교

- **이마**: 이마가 얼굴 폭의 ${Math.round(faceMetrics.foreheadWidthRatio * 100)}%를 차지하는 ${
    faceMetrics.foreheadWidthRatio > 0.95 ? "넓은" 
      : faceMetrics.foreheadWidthRatio > 0.88 ? "보통-넓은" 
      : "보통" } 편.
  Hint: ${regionScores[0].rationaleHint}
- ...
  `;
};
```

→ LLM이 "이 사람 이마는 93%" 같은 구체 데이터를 받으면 사진별 차별화된 문장 생성 가능.

단, 프롬프트 규칙("측정 수치 출력 금지")과 충돌 가능. 사용자에게 노출하지 말되 내부 입력으로만 사용하게 가드 강화 필요.

### 옵션 E — **모델 상향 (GPT-5.4 mini)** (이전 보고서 `02-` 참조)

- Instruction following 개선 → "사진마다 다르게" 지시를 더 잘 지킴
- 한국어 보수성은 여전할 수 있음 (영어 최적화라)
- **프롬프트 개선 없이 모델만 바꾸면 효과 제한적**

### 옵션 F — **섹션별 "사진별 관찰 토큰" 강제 삽입**

프롬프트에 다음을 요구:

```markdown
## 출력 형식 추가 규칙

1. `summary` 첫 문장은 반드시 **사진에서 직접 관찰 가능한 특징** 하나를 구체적으로 언급하며 시작할 것
   - 예: "이마 상단에서 눈썹까지의 선이 부드러워" / "코가 중심에서 살짝 왼쪽으로 치우친"
   - 금지: "전체적으로 조화롭고", "안정적인 인상이 강해요" 같은 일반 어휘 첫 문장

2. `interpretation`은 반드시 이미지에서 본 **구체 부위의 모양·방향·결**을 1회 이상 언급
```

→ 형식 강제로 LLM이 이미지를 무시할 수 없게 만듦.

## 💡 핵심 결론

### "Gemini 2.5 Flash 한계인가?"
→ **아니요, 주원인은 프롬프트·hint 설계**입니다.

- **Balance hint가 고정 문자열**이라 모든 사진이 똑같은 hint 받음 (가장 치명적)
- **Region hint가 3구간 템플릿**이라 한국인 평균 얼굴 80%가 동일 구간에 몰림
- 프롬프트가 **hint 복붙을 약하게 금지**만 하고 있어 LLM이 편한 길(복붙) 선택
- **이미지 관찰 지시가 약해서** LLM이 이미지보다 hint 블록에 의존

### 즉, 모델을 GPT-5.4 mini로 바꿔도 **프롬프트·hint를 그대로 두면 비슷한 현상 재발 가능**.

### 해결 우선순위
1. **Balance scorer hint 다양화** ← 최우선 (코드 5줄로 즉시 개선)
2. **Region hint 분기 세분화** ← 주효과
3. **이미지 관찰 지시 강화** ← 보조
4. (선택) 모델 상향 — 위 3개 적용 후 판단
