## 🔴 Phase 8 튜닝 실패 분석

### 1. `oneLineDefinition` 5종 톤 레인 → **미적용**

**기대**:
- "급발진과는 거리가 먼, 브레이크 성능 좋은 신중파 인상"
- "'인간 안전벨트' 같은 안정감 있는 상"

**실제**:
```
겉으론 차분, 속으론 단단, 말보다 행동으로 보여주는 타입
```

→ **reference overall.md의 "겉은 차분, 속은 단단, 말보다 행동으로 보여주는 타입"을 거의 그대로 복붙**.

이건 프롬프트의 공통 헤더에서 reference 톤 가이드로 쓰던 문구인데, LLM이 oneLineDefinition 예시로 오인. 5종 톤 레인(현대 비유/의인화/감각/속담/대사) 중 **어느 하나도 채택되지 않음**.

**원인**:
- 금지 패턴 리스트에 "안정감 있는 인상과 신중함이 돋보이는 상" 같은 **과거 실패 사례**만 넣다 보니, LLM이 "그럼 reference 원문을 쓰면 안전하겠다"로 수렴
- 5종 레인 예시가 많을수록 LLM이 가장 "안전해 보이는" 표현으로 가는 경향

**수정 방향**:
- 공통 헤더의 reference 문구도 금지 리스트에 추가
- 5종 레인 중 **랜덤하게 1개 레인을 지정**해서 프롬프트 생성 시 강제 (레인별 변동성 확보)
- 또는 5종 예시를 줄이고 **"이 5종 레인 중 하나로 반드시 창작. 예시 문구 복붙 금지"** 강조

### 2. `oneLiner` 패턴 상한 → **편향 축만 이동**

**기대**: 4종 이상 균등 분포, 동일 패턴 최대 3개

**실제** (부위별 oneLiner 8개):
1. "생각이 많아도, 끝은 늘 명확해요." — 역설형
2. "날카로운 눈빛, 놓치지 않는 승부." — 명사구+명사구
3. "단정한 눈썹, 흔들림 없는 소신." — 명사구+명사구
4. "반듯한 코, 곧게 뻗는 현실 감각." — 명사구+명사구
5. "차분한 입매, 묵직하게 남기는 말." — 명사구+명사구
6. "부드러운 턱선, 포용의 미학." — 명사구+명사구
7. "은은한 광대, 자연스러운 존재감." — 명사구+명사구
8. "균형 잡힌 상, 시간이 쌓는 가치." — 명사구+명사구

→ **7/8이 "형용사 명사, 형용사 명사구" 동일 패턴**. 프롬프트의 "동일 패턴 최대 3개" 규칙 **완전 무시**.

비교:
- result3: "A보다 B" 5/8 (편향 있음)
- result4: "명사구+명사구" 7/8 (**편향 심화**)

**원인**:
- LLM의 패턴 관성이 예상보다 강함. 한 번 패턴을 잡으면 나머지도 동일 패턴으로 수렴
- 자기검증 규칙("4개 이상이면 재작성")을 LLM이 자기 교차 검증 못함
- 5종 톤 레인 예시 중 명사구형이 많아서 그쪽으로 수렴

**수정 방향**:
- 부위별로 **패턴을 직접 할당** ("1번은 A보다 B형, 2번은 명사구형, 3번은 역설형…")
- 또는 출력 후 프로그래밍적으로 패턴 분석 → 편향 시 재호출
- 프롬프트 예시를 레인별로 1개씩만 (현재 3~4개씩 → 과다)

### 3. 시간·축적 은유 2개 상한 → **위반**

`nicknameSubtext` 3개 + `finalNote` = 4개 문장 중 시간·축적 등장 횟수:

| 위치 | 내용 | 시간·축적 은유 |
|---|---|---|
| 연애 nicknameSubtext | "곁에서 묵묵히 챙겨주는 온기" | ✅ 없음 |
| 재물 nicknameSubtext | "꾸준함으로 **쌓아 올리는** 든든함" | 🔴 **"쌓아 올리는"** |
| 직장 nicknameSubtext | "묵묵히 실력을 **쌓아가는** 단단함" | 🔴 **"쌓아가는"** (금지어 그대로) |
| finalNote | "관계가 **깊어질수록** 진가를 발휘하는" | 🔴 **"깊어질수록"** (시간 은유) |

→ **4개 중 3개**에서 시간·축적 등장. 프롬프트 상한(2개) 위반.

**원인**:
- "쌓아가는"을 금지 어휘로 명시했는데 LLM이 "쌓아 올리는"으로 변주해서 우회
- 금지 어휘 리스트가 고정 표현만 커버, 유사 표현을 못 잡음

**수정 방향**:
- 정규식·substring 수준이 아닌 **의미 수준의 금지**: "축적/성장/시간 경과" 개념 전체를 최대 2회로 제한 명시
- 대안 은유 리스트를 프롬프트에 구체 제시 (온기·무게·속도·빛·공간·리듬 등)

## 🎯 근본 처방 제안 (Phase 9)

Phase 8의 문제는 **"예시 추가 → LLM이 복붙 증가"** 의 역설. 근본 원인을 해결하는 방향으로:

### P0. `oneLineVerdict` 분야 간 오염 재방지 (즉시)
- Stage C 프롬프트에서 3개 분야 예시를 **한 리스트에 병렬 노출 금지**
- 각 분야 섹션 안에 **해당 분야 예시만** 격리 (다른 분야 예시는 생성 시점에 제거)

### P1. 프롬프트 예시 철학 전환
- **"이렇게 쓰세요" 예시 → "이렇게 쓰지 마세요" 금지 예시**로 전환
- 금지 리스트에 **이전 결과물의 프롬프트 예시 복붙 문구들 추가**
- 예시 대신 **"창작 공식"** 제시 (예: "[형용사] + [부위의 동작] + [시적 마침]")

### P2. `oneLineDefinition` 레인 강제 할당
- 프롬프트 생성 시 5종 레인 중 1개를 해시·랜덤으로 선택해 **"반드시 이 레인으로 창작"** 지시
- 결과적으로 사진마다 다른 레인 톤 출력

### P3. `oneLiner` 패턴 강제 분배
- 부위별로 패턴 할당: "1번은 A보다 B형, 2번은 명사구형, 3번은 역설형, 4번은 관점형… (순환)"
- LLM이 자율 결정 → 패턴 수렴이므로, 할당 방식으로 강제 분산

### P4. 시간·축적 은유 상위 개념 금지
- 단순 어휘("쌓아가는") 금지 → 변주("쌓아 올리는")로 우회됨
- **"시간 경과로 가치가 증명된다" 의미 자체를 최대 2문장으로 제한**
- 대안 은유 5~7개를 프롬프트에 구체 제시 (무게/온기/속도/빛/공간/리듬/깊이)
